# Phase 3 — UI Design Contract

> Visual and interaction contract for the Core Dashboard frontend phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn/ui (CLI) |
| Preset | Run `npx shadcn@latest init -t vite` — no custom preset string; shadcn default for Vite |
| Component library | Radix UI (via shadcn/ui) |
| Icon library | Lucide React (bundled with shadcn/ui) |
| Font | System font stack (Inter if available, system-ui fallback) — no custom web font load in Phase 3 |

**shadcn components to install:**

```bash
npx shadcn@latest add card badge button separator skeleton
```

- `card` — league card container (CardHeader, CardContent, CardTitle)
- `badge` — confidence band label (High / Medium / Low)
- `button` — "Snapshot now" manual trigger, drill-in navigation
- `separator` — visual divider between card sections
- `skeleton` — loading state for all dashboard data regions

**Tailwind version:** 4.2.2 (CSS-first config via `@tailwindcss/vite` plugin — no `tailwind.config.js`).
All custom tokens declared in `src/index.css` using `@theme` blocks.

---

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gaps, inline badge padding |
| sm | 8px | Compact element spacing within cards (e.g. between direction label and confidence badge) |
| md | 16px | Default card padding (`CardContent` inner spacing), button padding |
| lg | 24px | Card-to-card gap in the grid, section padding within drill-in view |
| xl | 32px | Page-level horizontal padding on the dashboard grid container |
| 2xl | 48px | Major section breaks within the league drill-in view |
| 3xl | 64px | Reserved; not used in Phase 3 |

Exceptions:
- Touch-target minimum for all interactive elements: 44px tall (applies to "Snapshot now" button and manager expand rows in drill-in)
- Card grid gap: `gap-4` (16px) on mobile, `gap-6` (24px) on lg breakpoint

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 (regular) | 1.5 |
| Label | 12px | 400 (regular) | 1.4 |
| Heading | 18px | 600 (semibold) | 1.2 |
| Display | 20px | 600 (semibold) | 1.2 |

**Usage mapping:**

- **Display (20px / 600):** Direction label text on the league card (e.g. "True Contender", "Hard Rebuild") — the single most prominent piece of information on each card
- **Heading (18px / 600):** League name in `CardTitle`; section headers in the drill-in view ("Value Risers", "Value Fallers", "Exploit Windows")
- **Body (14px / 400):** Primary weakness text on the card; riser/faller reason strings; exploit window action text; snapshot timestamp; all descriptive prose in the drill-in view
- **Label (12px / 400):** Secondary metadata — points delta values (e.g. "+8.2"), player names in risers/fallers list, confidence band text inside the Badge, "Last snapshot: 2 hours ago" timestamps, trigger type indicators

**Weight restriction:** Only two weights used — 400 and 600. Do not introduce 500 (medium) or 700 (bold).

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `hsl(var(--background))` — shadcn default near-white/near-black | Page background, dashboard grid container |
| Secondary (30%) | `hsl(var(--card))` — shadcn card surface | League cards, drill-in panel surfaces, risers/fallers table background |
| Accent (10%) | `hsl(var(--primary))` — shadcn default blue | Reserved elements listed below |
| Destructive | `hsl(var(--destructive))` — shadcn default red | Not used in Phase 3 — no destructive actions in this phase |

**Accent reserved for:**
1. "Snapshot now" button (primary variant)
2. Active/hover state on league card links (ring or shadow on focus)
3. High confidence badge background (`Badge variant="default"` maps to primary)
4. Points delta positive values (+X.X) in the risers list — accent green via `text-green-600` (Tailwind semantic)
5. Negative delta values (−X.X) in the fallers list — `text-red-600` (Tailwind semantic, not the destructive role)

**Semantic status colors (not part of 60/30/10 — informational only):**
- Confidence band "High" → `Badge variant="default"` (accent fill)
- Confidence band "Medium" → `Badge variant="secondary"` (muted fill)
- Confidence band "Low" → `Badge variant="outline"` (outlined, no fill)

**Dark mode:** shadcn/ui ships with CSS variable tokens that support dark mode via the `.dark` class. Phase 3 does not implement a mode toggle — the app loads in the OS default (prefers-color-scheme). The `@theme` block in `index.css` must include both `:root` and `.dark` token sets from the shadcn init output.

## Component Inventory

### LeagueCard (main dashboard)

**Source:** Custom composition of shadcn `Card` + `Badge` + `Link` (TanStack Router).

Layout (top to bottom, all within a fixed-height card):
1. `CardTitle` — league name (Heading, 18px/600, `text-muted-foreground`)
2. Direction label row — direction label text (Display, 20px/600) + confidence Badge side-by-side, `flex items-center gap-2`
3. `Separator`
4. Primary weakness paragraph (Body, 14px/400) — actionable nudge included in the string (e.g. "Thin at WR2 — 2 tradeable picks")
5. Top exploit window (Label, 12px/400, `text-muted-foreground`, `border-t pt-2`) — single line; hidden if null
6. Snapshot timestamp row (Label, 12px/400, `text-muted-foreground`) — "Last snapshot: 2 hours ago" or "No snapshot yet"

Card states:
- **Loading:** All text regions replaced with `Skeleton` components of matching height
- **Pending (Phase 2 data absent):** Direction label shows "Pending analysis", confidence badge shows "—", weakness shows "Analysis not yet run"
- **Hover:** `hover:shadow-md transition-shadow` — no color change, only shadow elevation

### RisersFallersList (drill-in view)

**Source:** Custom table using HTML `<table>` with Tailwind classes (no shadcn Table in Phase 3 — too heavy for a 10-row list).

Layout: Two columns ("Risers" and "Fallers") each with 5 rows.

Each row: player name (Label, 12px/400) | delta (Label, 12px/400, `text-green-600` or `text-red-600`) | reason string (Label, 12px/400, `text-muted-foreground`, truncated at 60 chars with ellipsis)

Empty state: "No actionable movers since last ingest." (Body, 14px/400, centered, `text-muted-foreground`)

### ExploitWindowPanel (drill-in view)

**Source:** Custom accordion-style list. Each manager row uses a `<details>` / `<summary>` pattern styled with Tailwind (no shadcn Accordion — avoids Radix overhead for simple expand/collapse).

- Collapsed row: manager name (Body, 14px/400) | trigger count badge (Label, 12px/400, `Badge variant="outline"`) | "High Opportunity" label if multiple triggers (Body, 14px/600, `text-primary`)
- Expanded: each trigger as a paragraph with suggested action in quotes (Body, 14px/400)
- Touch target for expand toggle: minimum 44px height

Empty state: "No behavioral triggers detected for this league." (Body, 14px/400, centered, `text-muted-foreground`)

### SnapshotStatus (present on both routes)

**Source:** Custom inline component (no shadcn wrapper needed).

Layout: timestamp text (Label, 12px/400) + "Snapshot now" `Button` (variant="default", size="sm") side by side, `flex items-center gap-2`.

States:
- Idle: "Last snapshot: {relative time}" + enabled button
- Pending (mutation in-flight): "Saving..." text, button disabled with `opacity-50`
- No snapshot yet: "No snapshot yet" + enabled button

## Interaction States

Every data region that fetches from the API must implement all four states:

| State | Behavior |
|-------|----------|
| Loading | Replace content with matching-height `Skeleton` components; no spinner |
| Success | Render data |
| Empty | Render empty state copy (see Copywriting Contract) |
| Error | Render error state copy inline (no full-page error); TanStack Query retry handles refetch |

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA (snapshot trigger) | "Snapshot now" |
| Empty state — no leagues connected | "No leagues connected. Add a league ID to get started." |
| Empty state — league card pending analysis | "Analysis not yet run" (direction label area) |
| Empty state — risers/fallers | "No actionable movers since last ingest." |
| Empty state — exploit windows | "No behavioral triggers detected for this league." |
| Empty state — snapshot status | "No snapshot yet" |
| Error state — dashboard fetch failed | "Dashboard data unavailable. Check that the backend is running, then refresh." |
| Error state — league drill-in fetch failed | "League data unavailable. Try refreshing or check the backend connection." |
| Error state — snapshot trigger failed | "Snapshot failed. Try again in a moment." (inline, below the button) |
| Pending analysis label | "Pending analysis" (direction label when Phase 2 data is absent) |
| Confidence band labels | "High" / "Medium" / "Low" (exact casing — never "HIGH" or "high") |
| Snapshot timestamp format | "Last snapshot: {N} minutes ago" / "Last snapshot: {N} hours ago" / "Last snapshot: {date}" (relative for <24h, absolute for older) |
| Snapshot in-flight | "Saving..." (replaces button label, button disabled) |
| Multiple triggers collapsed | "High Opportunity" (exact casing) |

**Destructive actions in Phase 3:** None. No delete, reset, or irreversible operations are exposed in this phase.

## Implementation Notes for Executor

1. **Tailwind v4 CSS-first config:** All token overrides go in `src/index.css` under `@theme {}`. No `tailwind.config.js` is created. The `@tailwindcss/vite` plugin in `vite.config.ts` handles compilation.

2. **shadcn init must run before any component work:** `npx shadcn@latest init -t vite` sets up the `@/` path alias in both `tsconfig.json` and `vite.config.ts`. Do not manually create components in `src/components/ui/` before init runs.

3. **Direction label text is free-form string from backend:** The 8 direction label options ("True Contender", "Fragile Contender", "Fringe Playoff", "Productive Struggle", "One-Year Punt", "Retool", "Elite Value Accumulation", "Hard Rebuild") are returned as strings from the API. The frontend renders them verbatim — no client-side mapping or transformation.

4. **Confidence band conversion happens server-side:** The FastAPI dashboard router converts the float `confidence` field (0.0–1.0) to "High" / "Medium" / "Low" before returning JSON. The frontend receives only the band label string, never the raw float.

5. **Skeleton dimensions must match content:** Skeletons for the direction label area should be `h-7 w-40`, for the weakness text `h-4 w-full`, for the timestamp `h-3 w-28`. Do not use generic full-width skeletons that misrepresent the content shape.

6. **League card minimum height:** `min-h-[180px]` — ensures consistent card grid appearance when exploit window or snapshot row is absent.
