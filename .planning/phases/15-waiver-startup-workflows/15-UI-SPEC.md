Declared values (multiples of 4 only). Inherited from project-wide Tailwind 4px unit scale.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline badge padding, bid range tier dots |
| sm | 8px | Compact row internal padding, checklist item gap |
| md | 16px | Default card padding (CardContent), form field gap |
| lg | 24px | Section padding (CardHeader), step gap in wizard |
| xl | 32px | Panel-to-panel gap within overview stack |
| 2xl | 48px | Major section breaks (Waivers tab → Startup tab) |
| 3xl | 64px | Page-level top padding |

Exceptions:
- Touch targets on bid increment buttons: minimum 44px height (WCAG 2.5.5)
- `.terminal-label` rows: 8px vertical padding (py-2), 0 between label and first row

## Color

All tokens are CSS custom properties defined in `index.css`. Values shown are dark-mode (primary rendering mode).

| Role | CSS Token | Dark HSL | Usage |
|------|-----------|----------|-------|
| Dominant (60%) | `--background` | hsl(221 69% 8%) | Page background, fullscreen overlays |
| Secondary (30%) | `--card` | hsl(216 85% 10%) | All Card surfaces, panel backgrounds, checklist item rows |
| Accent (10%) | `--accent` | hsl(156 100% 81%) | Reserved elements only (see below) |
| Primary interactive | `--primary` | hsl(199 100% 74%) | Waiver add CTA button, startup draft "Use Pick" CTA, active tab link |

**Accent (`--accent`) reserved for:**
- "Free claim" badge (player worth a waiver wire free claim, no FAAB bid)
- "Direction fit" positive indicator on startup build templates
- 30-day action plan "Priority 1" dot marker
- Bid confidence "High" badge background

**Primary (`--primary`) reserved for:**
- Primary CTA buttons only (Add to Waivers, Enter Startup Draft, Begin Intake)
- Active navigation tab link variant

**Destructive (`--destructive`) reserved for:**
- Drop / liquidate action badges in orphan intake checklist
- Dead roster spot flag labels

## Screen Architecture

Three new screens are added to the existing league drill-in (`/league/$leagueId`).

### Screen 1: Waiver Wire

**Route:** `/league/$leagueId/waivers`

**Navigation integration:** Add "Waivers" tab-link button to the existing tab row in `LeagueDetailPage` alongside Overview / Managers / Rookie Board. Uses same `buttonClasses({ variant: isWaiversRoute ? "default" : "outline" })` pattern.

**Layout:** Single-column card stack, same as Overview route. No sidebar.

**Panels (top to bottom):**

1. **WaiverIntelHeader** — Card with `terminal-label` "Waiver Wire" and CardTitle showing remaining FAAB budget as a display number (Manrope 28px/800). Below budget: a muted-foreground sentence stating current team direction and its FAAB posture (e.g., "True Contender — bid aggressively for win-now upgrades").

2. **WaiverPlayerList** — Card with `terminal-label` "Add Candidates". Each player row:
   - Player name (14px/600 Inter) + position Badge (variant="outline") + team name (12px muted-foreground)
   - FAAB bid range: two mono values (e.g., `$12 – $18`) with a muted dash separator. If free claim: accent-colored "Free Claim" badge instead of dollar range.
   - Urgency badge: one of `High` (primary/10 bg), `Medium` (secondary bg), or `Low` (outline). Derived from backend urgency signal.
   - Expand chevron (lucide ChevronDown) — on click, expands inline rationale text (14px/400, muted-foreground, leading-6). No separate route needed.
   - Rows separated by `divide-y divide-border/40`.

3. **WaiverEmptyState** — shown when no add candidates exist. See copywriting contract.

**No modal or sheet.** Rationale inline-expand keeps the memo-like feel.

---

### Screen 2: Startup Draft Mode

**Route:** `/league/$leagueId/startup`

**Navigation integration:** "Startup Draft" tab-link added to the league tab row. Only rendered when the backend returns `league.startup_mode_available: true` (a new flag). If the flag is false, the tab is hidden entirely — no disabled state.

**Activation:** Startup mode is not a toggle in the UI. The backend determines eligibility based on league settings (Sleeper draft type). The frontend renders the tab when eligible.

**Layout:** Single-column card stack.

**Panels (top to bottom):**

1. **StartupDraftContextCard** — Card with `terminal-label` "Startup Draft" and the league name as CardTitle. Below: direction label (Manrope 22px/800) and one-sentence build template hint (14px/400, muted-foreground). E.g., "True Contender build: prioritize proven starters, avoid late-round upside picks."

2. **StartupPickValuationList** — Card with `terminal-label` "Pick Valuation". Each pick row:
   - Pick slot label (mono 14px: e.g., `1.01`) + projected player name (14px/600) + tier badge (variant="outline")
   - Trade-up recommendation: if trade-up is recommended, show a primary-colored "Trade Up" badge. If trade-down: muted "Trade Down" badge.
   - Rows separated by `divide-y divide-border/40`.

3. **StartupBuildTemplatePanel** — Card with `terminal-label` "Direction Build Templates". Three collapsible sections (each a `<details>` element styled to match the card aesthetic), one per template archetype (e.g., "Win-Now Stack", "Balanced Build", "Rebuild Mode"). Each section contains:
   - A heading (16px/600) + 3–5 bullet sentences (14px/400, muted-foreground, leading-6).
   - The recommended template for this team's direction has an accent left-border (`border-l-2 border-accent`).

4. **StartupEmptyState** — shown when startup data is unavailable. See copywriting contract.

---

### Screen 3: Orphan Intake Checklist

**Route:** `/league/$leagueId/orphan-intake`

**Navigation integration:** "Orphan Intake" tab-link added to the league tab row. Only rendered when backend returns `league.orphan_intake_available: true`. Hidden entirely when unavailable.

**Layout:** Single-column card stack. This is NOT a wizard/stepper — it renders all sections at once as a scannable memo. A stepper would be too much friction for a personal tool. Each section is a Card.

**Panels (top to bottom):**

1. **OrphanIntakeStatusCard** — Card with `terminal-label` "Orphan Intake" and a display-size (Manrope 28px/800) overall assessment label (e.g., "Salvageable", "Requires Liquidation", "Hidden Value"). Muted-foreground sub-sentence with one-line summary.

2. **AgeCurveRiskPanel** — Card with `terminal-label` "Age Curve Risk". A compact table (no `<table>` element — use div rows with `flex justify-between`) showing each player flagged for age-cliff risk. Columns: name / position badge / age / risk label badge. Badge colors: `border-destructive/25 bg-destructive/10 text-destructive` for high risk, `border-border/60 bg-transparent text-muted-foreground` for moderate.

3. **PickCapitalPanel** — Card with `terminal-label` "Pick Capital". List of future picks grouped by year (sub-section headers using `terminal-label`). Each pick: round badge + source team (muted-foreground 12px). Score summary sentence at top (14px/600): e.g., "Pick capital is below league median. Prioritize acquiring first-round assets."

4. **DeadRosterPanel** — Card with `terminal-label` "Dead Roster Spots". Each dead spot as a row: player name + position badge + `terminal-label` "DEAD" badge (destructive color). Liquidation option sentence below each (14px/400, muted-foreground). Empty state: "No dead roster spots detected."

5. **LineupViabilityPanel** — Card with `terminal-label` "Lineup Viability". Reuses the same slot-score grid pattern as `LineupStrengthCard` (2-col grid on lg, 1-col on sm). Slots flagged as below replacement-level use `border-destructive/25 bg-destructive/10` instead of `border-border/50 bg-card/40`.

6. **LiquidationOptionsPanel** — Card with `terminal-label` "Liquidation Options". A ranked list of assets recommended for sale/trade. Each row: player name + position badge + "Sell Now" or "Package" label (muted badge) + one-sentence rationale (14px/400, muted-foreground).

7. **ThirtyDayActionPlanCard** — Card with `terminal-label` "30-Day Action Plan" and CardTitle "Your First Month". Numbered list (1–5 items). Each item:
   - Priority dot: Item 1 uses accent color (`bg-accent/80`), items 2–3 use primary/30, items 4–5 use border/60.
   - Action headline (14px/600) + rationale sentence (14px/400, muted-foreground).
   - No separate export surface — the card is the artifact. User can screenshot or copy text.

## Interaction States

All states must be implemented for every data-fetching panel.

| State | Pattern |
|-------|---------|
| Loading | `<Skeleton className="h-24 w-full" />` inside CardContent, matches existing project pattern |
| Error | Card + CardContent + 14px muted-foreground sentence: problem description + "Try refreshing or re-running ingest." |
| Empty | Card + CardHeader (terminal-label + CardTitle) + CardContent with 14px muted-foreground explanation + next-step instruction |
| Data | Full panel content as specified above |
