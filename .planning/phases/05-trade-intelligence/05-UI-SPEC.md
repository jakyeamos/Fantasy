# Phase 5 — UI Design Contract

> Visual and interaction contract for the Trade Intelligence frontend phase. Generated by gsd-ui-researcher. Extends Phase 3 and Phase 4 design contracts — all prior tokens and patterns are inherited.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn/ui (CLI) — inherited from Phase 3 |
| Preset | `npx shadcn@latest init -t vite` (same as Phases 3–4 — no new preset) |
| Component library | Radix UI (via shadcn/ui) |
| Icon library | Lucide React (bundled with shadcn/ui) |
| Font | System font stack (Inter if available, system-ui fallback) — no custom web font load |

**Components already installed (do not reinstall):**

```bash
# Phase 3
card, badge, button, separator, skeleton
# Phase 4
tabs, table, alert
```

**New Phase 5 components to install:**

```bash
npx shadcn@latest add sheet input command popover scroll-area
```

- `sheet` — reroute panel (slide-in from right, triggered by "See reroutes")
- `input` — player/pick search text field in trade input
- `command` — combobox-style player/pick search with autocomplete (used inside `popover`)
- `popover` — anchor for `command` dropdown on the player search input
- `scroll-area` — scrollable asset list within each trade party's send/receive sides

**Tailwind version:** 4.2.2 (CSS-first config via `@tailwindcss/vite` — no `tailwind.config.js`). All token additions go in `src/index.css` under `@theme {}`.

## Typography

Inherited from Phase 3 and Phase 4. No new sizes or weights introduced.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 (regular) | 1.5 |
| Label | 12px | 400 (regular) | 1.4 |
| Heading | 18px | 600 (semibold) | 1.2 |
| Display | 20px | 600 (semibold) | 1.2 |

**Phase 5 usage mapping (additions to Phases 3–4):**

- **Display (20px / 600):** Strategic distinction banner headline — e.g. "Market fair — but moves you away from your rebuild" — the single most prominent output of the evaluator
- **Heading (18px / 600):** "Evaluate Trade" page heading; "Evaluation" section header; "Package Builder" section header; reroute sheet heading ("Better Options")
- **Body (14px / 400):** Dimension score reasoning strings (one line per dimension); reroute one-line reasoning; package builder offer reasoning; pick slot projected range text; search input placeholder text; party label text ("You send" / "You receive" / "They send" / "They receive")
- **Label (12px / 400):** Dimension name labels; confidence inline label "(low confidence)"; pick slot identity text (e.g. "Mike's 2026 1st"); projected draft slot badge text; asset names in the package builder output; "Fair range:" / "Best version:" / "Opening offer:" labels

**Weight restriction:** Only 400 and 600. Do not introduce 500 (medium) or 700 (bold) — same constraint as Phases 3–4.

## Color

Inherited from Phase 3 and Phase 4 shadcn CSS variable tokens. No new token roles added.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `hsl(var(--background))` — shadcn default near-white/near-black | Page background, trade evaluator container |
| Secondary (30%) | `hsl(var(--card))` — shadcn card surface | Trade input column cards, evaluation output card, reroute sheet background, package builder card |
| Accent (10%) | `hsl(var(--primary))` — shadcn default blue | Reserved elements listed below |
| Destructive | `hsl(var(--destructive))` — shadcn default red | Not used in Phase 5 — no destructive actions in this phase |

**Accent reserved for (Phase 5 additions):**
1. "Evaluate" primary action button (variant="default")
2. "See reroutes" button (variant="default") — the natural next action after reading scores
3. Active party column header border (left-side `border-l-2 border-primary` indicating the user's team column)
4. Pick slot projected draft slot badge — `bg-primary/10 text-primary` (muted accent fill) — distinguishes picks from players visually
5. Dimension score progress fill — `bg-primary` — fill width proportional to normalized score (0–100)

**Strategic distinction banner color (new Phase 5 pattern):**
- Banner is the most important single output — it must be impossible to miss
- Background: `bg-amber-50 dark:bg-amber-950/20`
- Border: `border-l-4 border-amber-500` (left accent bar, not full border — draws eye more than a box)
- Headline text: `text-amber-900 dark:text-amber-100` (Display, 20px/600)
- Sub-text: `text-amber-800 dark:text-amber-200` (Body, 14px/400)
- Icon: `TrendingDown` or `TrendingUp` from Lucide React, `text-amber-600` — icon communicates directional impact, not error
- Rationale: Amber with left-bar treatment creates a "callout" pattern distinct from both the LOW CONFIDENCE amber Alert (Phase 4 square box) and error states. This is a signal worth reading, not a warning about data quality.

**"Market fair" vs. "Strategically advancing" distinction:**
- "Market fair, strategically advancing" banner: same amber treatment — the direction is positive but the callout still warrants attention
- "Market fair, strategically neutral": `bg-muted border-l-4 border-muted-foreground/30` — muted callout, not hidden but subdued
- All three banner states always render — never hide the distinction callout

**Low-confidence dimension row styling:**
- Dimension name: `text-muted-foreground` (instead of `text-foreground`)
- Score value: `text-muted-foreground` (same as Phase 4 LOW CONFIDENCE score dimming)
- "(low confidence)" inline label: Label, 12px/400, `text-muted-foreground italic`, appended after the dimension name — source: CONTEXT.md D-07

**Semantic status colors (informational — not part of 60/30/10):**
- Dimension score 80–100: `text-green-600` (strong signal)
- Dimension score 50–79: `text-foreground` (neutral signal)
- Dimension score 0–49: `text-red-600` (weak/negative signal)
- These colors apply to the numeric score value only — not the dimension name or reasoning text

**Dark mode:** OS-default via `prefers-color-scheme` — same as Phases 3–4. No mode toggle in Phase 5.

## Component Inventory

### TradeEvaluatorPage (`/trades` or `/league/:leagueId/trades/new`)

**Source:** Custom page layout. Route detail is deferred (Claude's Discretion per CONTEXT.md) — executor chooses the route structure. The page must be reachable from three entry points: manager dossier, league drill-in, and standalone — source: CONTEXT.md D-04.

Layout (top to bottom):
1. Page heading — "Evaluate Trade" (Heading, 18px/600)
2. `TradeInputPanel` — trade party columns
3. "Evaluate" primary button (`Button variant="default"`, full-width on mobile, auto-width on desktop, 44px height)
4. `EvaluationOutputPanel` — shown only after evaluation runs; hidden before first evaluation
5. `RerouteSheet` — shadcn `Sheet` triggered by "See reroutes" button; overlays the page from the right
6. `PackageBuilderPanel` — shown only after user clicks "Build Package" from the evaluation output

### TradeInputPanel

**Source:** Custom grid layout. Uses `Card` + `ScrollArea` + `Input` + `Command` + `Popover`.

Layout: horizontal flex of party columns, `grid grid-cols-1 md:grid-cols-2 lg:grid-cols-3 gap-4`
- Phase 5 supports up to 3 parties (source: CONTEXT.md D-02)
- Default state: 2 party columns ("Your team" + one counterparty). Third party column appears only when user explicitly adds it.
- "Add a third party" affordance: `Button variant="ghost"` at the end of the column row — `text-muted-foreground`

Each party column (`Card` + `CardContent`):
1. Party header row: party label editable via `Input` (Body, 14px/400) — defaults to "Your Team" for the user's column, "Counterparty" for others. Party label input is borderless inline style (`border-none shadow-none focus-visible:ring-0`) — edit-in-place, not a form field.
2. "User's team" column: left border accent `border-l-2 border-primary` applied to the `Card` — visually identifies the user's perspective column
3. "You send" / "They send" sub-label (Label, 12px/400, `text-muted-foreground`) above the send asset list
4. Asset list — `ScrollArea` with `max-h-[200px]`, `flex flex-col gap-1` — each asset is a chip (see `AssetChip` below)
5. Player search combobox — `Popover` wrapping `Command` — trigger is an `Input` with placeholder "Search players or picks..." (Body, 14px/400)
6. "You receive" / "They receive" sub-label below a `Separator`
7. Second asset list (same structure as send list)

**Three-party evaluation note:** Evaluation always scores from the user's team perspective regardless of party count — source: CONTEXT.md D-02. The party column labeled "Your Team" is the reference point; all 7 dimension scores reflect that team's outcome.

### AssetChip (within TradeInputPanel)

**Source:** Custom inline component. No shadcn wrapper.

Layout: `inline-flex items-center gap-1 rounded-md px-2 py-1 bg-secondary text-sm` (Label, 12px/400)
- Player chip: player name (Label, 12px/400) + position badge (Label, 12px/400, `Badge variant="outline"`, 2-letter position code)
- Pick chip: pick identity text (Label, 12px/400, `text-muted-foreground italic`) + projected slot badge (`bg-primary/10 text-primary`, Label, 12px/400) — e.g. "Mike's 2026 1st" + "~1.04 projected" — source: CONTEXT.md D-03
- Remove button: `X` icon (`Lucide X`, 12px), `text-muted-foreground hover:text-foreground`, `ml-1`, 24px touch area minimum (chip itself is non-interactive row — remove is the only affordance)

### EvaluationOutputPanel

**Source:** Custom layout using `Card` + `CardContent`. Rendered below `TradeInputPanel` after evaluation runs.

Layout (top to bottom):
1. **Strategic distinction banner** — always the first element, full-width, impossible to miss — source: CONTEXT.md D-06
   - See `StrategicDistinctionBanner` component spec below
2. **Dimension score list** — 7 rows, one per dimension — source: REQUIREMENTS.md TRADE-01
   - Dimensions (in display order): Market Fairness | Roster Fit | Direction Fit | Timing Quality | Insulation Gain/Loss | Liquidity Gain/Loss | Manager Exploit Quality
   - See `DimensionScoreRow` component spec below
3. **"See reroutes" button** — `Button variant="default"` — appears below the 7 dimension rows as the natural next action — source: CONTEXT.md D-08. Label: "See reroutes"
4. **"Build Package" button** — `Button variant="outline"` — appears alongside "See reroutes". Label: "Build Package"

### StrategicDistinctionBanner

**Source:** Custom component. Not shadcn `Alert` — distinct visual treatment from Phase 4 LOW CONFIDENCE banner.

Layout: `flex items-start gap-3 rounded-lg p-4 border-l-4` with amber or muted color classes (see Color section for three states)
1. Icon — `TrendingUp` or `TrendingDown` from Lucide React (20px), `text-amber-600` for amber states, `text-muted-foreground` for muted state
2. Content: `flex flex-col gap-1`
   - Banner headline (Display, 20px/600) — e.g. "Market fair — but moves you away from your rebuild"
   - One-sentence explanation (Body, 14px/400) — e.g. "This trade rates as value-neutral by market but reduces your rebuild timeline by adding a win-now piece."

**Three banner states:**
- Strategically negative (market-fair but wrong direction): amber treatment (see Color section)
- Strategically advancing (market-fair and right direction): amber treatment — still a prominent callout
- Strategically neutral (market-fair, no directional impact): muted treatment — subdued but always present

### DimensionScoreRow

**Source:** Custom row component.

Layout: `flex items-center gap-3 py-2 min-h-[44px]` (44px touch target)
1. Dimension name (Label, 12px/400) — `w-40 shrink-0` — color: `text-foreground` normally, `text-muted-foreground` if low confidence
2. "(low confidence)" inline label (Label, 12px/400, `text-muted-foreground italic`) — conditional, appended after dimension name — source: CONTEXT.md D-07
3. Score bar — `flex-1 h-1.5 bg-muted rounded-full overflow-hidden` — fill `bg-primary` proportional to score
4. Score number (Label, 12px/400) — `w-8 text-right` — color: `text-green-600` for 80–100, `text-foreground` for 50–79, `text-red-600` for 0–49 (see Color section)
5. Reasoning string (Body, 14px/400, `text-muted-foreground`) — one line, no truncation — `mt-0.5 text-sm` on a second row below the score bar row (`flex-col` layout for the inner content after the dimension name)

## Interaction States

Every data region that fetches from the API implements all four states (inherited from Phase 3):

| State | Behavior |
|-------|----------|
| Loading | Replace content with matching-height `Skeleton` components; no spinner |
| Success | Render data |
| Empty | Render empty state copy (see Copywriting Contract) |
| Error | Render error state copy inline (no full-page error); TanStack Query retry handles refetch |

**Trade input state (Phase 5 additions):**

| State | Behavior |
|-------|----------|
| No assets added | "Evaluate" button disabled (`opacity-50 cursor-not-allowed`); disabled state persists until at least one asset is added to each of the user's send and receive sides |
| Player search loading | `Command` item list replaced with a `Skeleton` placeholder while API search resolves |
| Player search empty | "No players found." (Body, 14px/400, `text-muted-foreground`, centered within the `Command` dropdown) |
| Evaluation in flight | "Evaluate" button disabled + label changes to "Evaluating..." (`opacity-75`); `EvaluationOutputPanel` shows skeleton layout |

**Strategic banner state persistence:**
- Banner renders at all times once evaluation runs — it does not disappear on re-evaluate
- When re-evaluating with a modified trade, banner updates inline (no flash or animation needed)

## Implementation Notes for Executor

1. **Inherit all Phase 3 and Phase 4 token setup:** `src/index.css` `@theme {}` block is set by Phase 3 and unchanged through Phase 4. Do not overwrite. No new tokens are required in Phase 5.

2. **Strategic distinction banner is not an Alert:** Do not use shadcn `Alert` for the strategic distinction banner — the amber `Alert` is reserved for Phase 4's LOW CONFIDENCE pattern. The banner uses a custom `div` with the left-bar border treatment (see Color section). Using `Alert` would create visual confusion between two semantically distinct concepts.

3. **shadcn `Sheet` side="right" default:** The `Sheet` component from shadcn opens from the right by default. Use this default. Set `SheetContent` width via `className="w-[360px] sm:w-[420px]"`. The sheet overlays the page — it does not push content.

4. **shadcn `Command` within `Popover`:** Use the shadcn pattern: `Popover > PopoverTrigger > Input` + `PopoverContent > Command > CommandInput + CommandList`. The `Input` in `PopoverTrigger` acts as the visible search field; `CommandInput` is hidden (used for internal Command state). This pattern avoids a double-input UI while retaining Command's filtering logic.

5. **Player search is debounced:** The player/pick search `Command` should debounce API calls at 300ms. Do not fire on every keystroke.

6. **Evaluation output panel gating:** `EvaluationOutputPanel` (including the strategic banner, dimension rows, "See reroutes" button, and "Build Package" button) is conditionally rendered — it does not exist in the DOM before the first evaluation run. Use a `null` return, not `invisible` or `opacity-0`. The panel appears after the first successful evaluation response.

7. **Package builder in-page expansion:** `PackageBuilderPanel` expands below `EvaluationOutputPanel` — it does not open a sheet or modal. Use a conditional render with `mt-6` gap below the evaluation panel. Smooth height transition optional but not required.

8. **Three-party column layout:** The `TradeInputPanel` uses a CSS grid that shifts from `grid-cols-2` (default) to `grid-cols-3` when the third party column is added. The "Add a third party" ghost button occupies the third column slot until clicked, then is replaced by the new party column.

9. **"Evaluate Trade" entry points in Phases 3–4:** Two existing pages need a button added:
   - `DossierPage` header (Phase 4): add `Button variant="outline"` labeled "Evaluate Trade" next to the page heading. The button navigates to the trade evaluator route.
   - League drill-in page (Phase 3): add a `Button variant="outline"` labeled "Evaluate Trade" in the page header area. Navigator to the trade evaluator route.

10. **Skeleton dimensions for evaluation output:**
    - Strategic banner skeleton: `h-16 w-full rounded-lg`
    - Each dimension row skeleton: `h-11 w-full` × 7
    - Reroute card skeleton: `h-16 w-full` × 2
    - Package builder offer card skeleton: `h-32 w-full` × 2

11. **Pick identity is specific, not abstract:** Picks are entered by owner (e.g. "Mike's 2026 1st") — source: CONTEXT.md D-03. The `Command` search for picks should surface picks by owner name + year + round. The projected draft slot badge is a separate display field — it is not part of the pick identity string.
