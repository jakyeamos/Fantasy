# Phase 4 — UI Design Contract

> Visual and interaction contract for the Manager Profiling frontend phase. Generated by gsd-ui-researcher. Extends Phase 3 design contract — all Phase 3 tokens and patterns are inherited.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn/ui (CLI) — inherited from Phase 3 |
| Preset | `npx shadcn@latest init -t vite` (same as Phase 3 — no new preset) |
| Component library | Radix UI (via shadcn/ui) |
| Icon library | Lucide React (bundled with shadcn/ui) |
| Font | System font stack (Inter if available, system-ui fallback) — no custom web font load |

**Phase 3 components already installed (do not reinstall):**

```bash
# Installed in Phase 3 — available for reuse
card, badge, button, separator, skeleton
```

**New Phase 4 components to install:**

```bash
npx shadcn@latest add tabs table alert
```

- `tabs` — dossier tabbed navigation (Overview | Trade History | Pitch Angles)
- `table` — trade history list in Trade History tab
- `alert` — LOW CONFIDENCE banner in Overview tab (amber/warning styling)

**Tailwind version:** 4.2.2 (CSS-first config via `@tailwindcss/vite` — no `tailwind.config.js`). All token additions go in `src/index.css` under `@theme {}`.

## Spacing Scale

Inherited from Phase 3. No new values added.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gaps, inline badge padding |
| sm | 8px | Compact element spacing within cards (e.g. between manager name and exploitability score) |
| md | 16px | Default card/panel padding, tab content inner spacing |
| lg | 24px | Section padding within dossier tabs, gap between dossier header and tab panel |
| xl | 32px | Page-level horizontal padding on the managers list container |

Exceptions:
- Touch-target minimum for all interactive elements: 44px tall (manager list rows, tab triggers, expand toggles) — inherited from Phase 3
- Tab trigger height: 44px minimum (satisfies touch target requirement)
- Exploitation type badge: `px-2 py-1` (8px/4px) — compact inline badge, no touch target required (non-interactive)

## Typography

Inherited from Phase 3. No new sizes or weights introduced.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 (regular) | 1.5 |
| Label | 12px | 400 (regular) | 1.4 |
| Heading | 18px | 600 (semibold) | 1.2 |
| Display | 20px | 600 (semibold) | 1.2 |

**Phase 4 usage mapping (additions to Phase 3):**

- **Display (20px / 600):** Manager name in the dossier header
- **Heading (18px / 600):** Tab section headers ("Trade History", "Pitch Angles"), "Managers" page heading
- **Body (14px / 400):** Pitch angle reasoning text, exploitation evidence summary strings (e.g. "Lost value on 7 of 10 trades"), positional needs list, aggregate trade stats
- **Label (12px / 400):** Exploitability score co-located evidence count ("74 | 14 trades"), secondary exploitation type badge text, pitch angle "what to send / what to avoid" detail lines, trade history row metadata (date, value delta), "LOW CONFIDENCE" banner sub-text count

**Weight restriction:** Only 400 and 600. Do not introduce 500 (medium) or 700 (bold) — same constraint as Phase 3.

## Color

Inherited from Phase 3 shadcn CSS variable tokens. No new token roles added.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `hsl(var(--background))` — shadcn default near-white/near-black | Page background, managers list container, dossier page background |
| Secondary (30%) | `hsl(var(--card))` — shadcn card surface | Manager list row cards, dossier panel surface, tab content area background |
| Accent (10%) | `hsl(var(--primary))` — shadcn default blue | Reserved elements listed below |
| Destructive | `hsl(var(--destructive))` — shadcn default red | Not used in Phase 4 — no destructive actions in this phase |

**Accent reserved for (Phase 4 additions):**
1. Exploitability score numeric value — `text-primary` — draws attention to the key signal
2. "View Dossier" navigation link/button (primary variant) on the managers list
3. Active tab indicator on dossier tabs (`TabsTrigger` active state uses primary underline)
4. Pitch angle deal archetype label text (e.g. "Win-now swap") — `text-primary font-semibold`
5. Positive value delta in trade history (+X.X) — `text-green-600` (Tailwind semantic, same as Phase 3 risers)
6. Negative value delta in trade history (−X.X) — `text-red-600` (Tailwind semantic, same as Phase 3 fallers)

**LOW CONFIDENCE banner color:**
- Background: `bg-amber-50 dark:bg-amber-950/20`
- Border: `border-amber-200 dark:border-amber-800`
- Icon + heading text: `text-amber-800 dark:text-amber-300`
- Body text: `text-amber-700 dark:text-amber-400`
- Rationale: Amber (warning) rather than destructive red — this is a trust calibration signal, not an error. Red would suggest something is broken; amber signals "proceed with appropriate skepticism." Source: CONTEXT.md D-16 (Claude's Discretion).

**Exploitation type badge colors:**
- Primary type badge: `Badge variant="default"` (accent fill) — most prominent
- Secondary type badge: `Badge variant="secondary"` (muted fill) — less prominent
- Exploitation type labels (exact strings — never vary casing):
  - "value-loss trader"
  - "timing-error trader"
  - "directionally-incoherent trader"
  - "archetype-specific overpayer"

**Exploitability score dimming (LOW CONFIDENCE state):**
- Score number: `text-muted-foreground` instead of `text-primary` — visually deprioritized
- Score row: `opacity-75` applied to the entire score + evidence count row

**Semantic status colors (informational — not part of 60/30/10):**
- HIGH confidence: `Badge variant="default"` (accent fill) — inherited from Phase 3
- MEDIUM confidence: `Badge variant="secondary"` (muted fill) — inherited from Phase 3
- LOW confidence: `Badge variant="outline"` (no fill) — inherited from Phase 3

**Dark mode:** OS-default via `prefers-color-scheme` — same as Phase 3. No mode toggle in Phase 4.

## Component Inventory

### ManagersListPage (`/league/:leagueId/managers`)

**Source:** Custom page layout. No new shadcn wrapper — uses existing `Card` + `Badge` + `Button` + new `Separator`.

Layout:
1. Page heading — "Managers" (Heading, 18px/600) + league name in `text-muted-foreground` (Body, 14px/400), `flex items-baseline gap-2`
2. Manager list — vertical stack, `flex flex-col gap-3`
3. Each row is a `Card` with `CardContent` containing a 3-row layout (see ManagerListRow below)

### ManagerListRow (within ManagersListPage)

**Source:** Custom composition of `Card` + `Badge` + `Link` (TanStack Router).

Layout (within a single card, top to bottom):
1. Top row: manager name (Body, 14px/400, `font-semibold`) + direction label Badge (`Badge variant="secondary"`, Label 12px/400) + exploitability score display (Label, 12px/400) — all `flex items-center gap-2 justify-between`
2. Score display format: "Exploitability: **74** | 14 trades" where the score number is `text-primary font-semibold` (Body/Label hybrid — 14px/600) and the evidence count is `text-muted-foreground` (Label, 12px/400)
3. LOW CONFIDENCE score state: score number uses `text-muted-foreground opacity-75` instead of `text-primary`
4. Preview row: top 1 pitch angle — deal archetype label (Label, 12px/400, `text-primary`) followed by one-sentence reasoning (Label, 12px/400, `text-muted-foreground`, truncated at 80 chars with ellipsis), `mt-1`
5. No exploitation type on the list row — source: CONTEXT.md D-02

Card states:
- **Loading:** `Skeleton` components matching the 3-row layout heights
- **Hover:** `hover:shadow-md transition-shadow` — same as Phase 3 LeagueCard
- **Touch target:** entire card is a `Link` wrapper — minimum card height 60px

### DossierPage (`/league/:leagueId/managers/:managerId`)

**Source:** Page using shadcn `Tabs` (TabsList, TabsTrigger, TabsContent) + `Card` header.

Layout:
1. Dossier header — fixed above tabs, not part of any tab content
   - Manager name (Display, 20px/600)
   - Direction badge (`Badge variant="secondary"`) + confidence badge (inherited Phase 3 confidence badge pattern)
   - Exploitability score: "Exploitability: **74** | 14 trades" — same format as list row but larger context (Body, 14px/400 for label, 14px/600 for score number)
   - LOW CONFIDENCE header state: score number uses `text-muted-foreground opacity-75`
2. `TabsList` below header — 3 triggers: "Overview" | "Trade History" | "Pitch Angles"
   - `TabsTrigger` height: 44px minimum
   - Active tab: primary color underline (shadcn default TabsTrigger active state)
3. Tab content areas (see individual tab components below)

### DossierOverviewTab (TabsContent value="overview")

**Source:** Custom composition within `TabsContent`.

Layout (top to bottom):
1. LOW CONFIDENCE Alert (conditional — shown only when evidence count < MIN_TRADE_EVIDENCE_THRESHOLD)
   - Uses shadcn `Alert` component with amber styling (see Color section)
   - Heading: "LOW CONFIDENCE" (Label, 12px/600, `text-amber-800 dark:text-amber-300`)
   - Body: "Based on {N} trades (minimum 10 for reliable profiling). Treat all conclusions with skepticism." (Body, 14px/400, `text-amber-700 dark:text-amber-400`)
   - Icon: `AlertTriangle` from Lucide React, `text-amber-600`
2. Exploitation type section
   - Section label "Exploitation Type" (Heading, 18px/600, `mb-2`)
   - Primary type Badge (`variant="default"`, large) + secondary type Badge (`variant="secondary"`, smaller, `ml-2`) side by side
   - Evidence summary string below each type (Body, 14px/400, `text-muted-foreground`) — e.g. "Lost value on 7 of 10 trades"
3. Roster summary section
   - Section label "Roster Summary" (Heading, 18px/600)
   - Direction label + likely direction reasoning (Body, 14px/400)
   - Positional needs list — `ul` with `li` items (Body, 14px/400), max 4 items
4. Aggregate trade stats row
   - Horizontal `flex gap-6` of stat cells: Total Trades | Win Rate (value received / sent) | Avg Value Delta
   - Stat number (Display, 20px/600) + stat label below (Label, 12px/400, `text-muted-foreground`)
5. `Separator` between each section — `my-4`

### DossierTradeHistoryTab (TabsContent value="trade-history")

**Source:** shadcn `Table` component.

Layout:
- Table columns: Date | Assets Sent | Assets Received | Value Delta
- Date column (Label, 12px/400) — formatted as "MMM YYYY" (e.g. "Jan 2025")
- Assets columns (Body, 14px/400) — comma-separated player/pick names, truncate at 40 chars per cell
- Value Delta column (Label, 12px/400) — `text-green-600` for positive, `text-red-600` for negative
- Rows grouped by recency: "Last 12 Months" and "Older" — group headings use (Label, 12px/600, `text-muted-foreground`, sticky-like visual separation via `bg-muted/50 px-4 py-1`)
- Default sort: newest trade first within each group

Table states:
- **Loading:** 5 skeleton rows, each matching table row height (44px)
- **Empty:** "No trade history found for this manager." (Body, 14px/400, centered, `text-muted-foreground`, full table width)
- **Error:** "Trade history unavailable. Try refreshing." (Body, 14px/400, centered, inline — no full-page error)

### DossierPitchAnglesTab (TabsContent value="pitch-angles")

**Source:** Custom card-per-angle layout. Uses `Card` + `CardContent`.

Layout (2–3 cards stacked vertically, `flex flex-col gap-4`):

Each pitch angle card:
1. Deal archetype label (Heading, 18px/600, `text-primary`) — e.g. "Win-now swap"
2. Two detail rows:
   - "Send:" label (Label, 12px/400, `text-muted-foreground`) + value (Body, 14px/400) side by side
   - "Avoid:" label (Label, 12px/400, `text-muted-foreground`) + value (Body, 14px/400) side by side
3. Reasoning sentence (Body, 14px/400, `text-muted-foreground italic`, `mt-2 pt-2 border-t`) — one sentence, no truncation

Card states:
- **Loading:** 2 skeleton cards matching card height (~100px each)
- **Empty:** "No pitch angles available yet. More trade history is needed to compute angles." (Body, 14px/400, centered, `text-muted-foreground`)
- **Error:** "Pitch angles unavailable. Try refreshing." (Body, 14px/400, centered)

## Interaction States

Every data region that fetches from the API implements all four states (inherited from Phase 3):

| State | Behavior |
|-------|----------|
| Loading | Replace content with matching-height `Skeleton` components; no spinner |
| Success | Render data |
| Empty | Render empty state copy (see Copywriting Contract below) |
| Error | Render error state copy inline (no full-page error); TanStack Query retry handles refetch |

**LOW CONFIDENCE state (Phase 4 addition):**
- Triggered when evidence count < `MIN_TRADE_EVIDENCE_THRESHOLD` (10 trades — constant from backend)
- Amber `Alert` banner renders at top of Overview tab
- Exploitability score number switches from `text-primary` to `text-muted-foreground opacity-75`
- All other dossier content renders normally — LOW CONFIDENCE is a calibration label, not a blocker

**Tab persistence:**
- Active tab state is local component state (not URL param) — navigating back resets to "Overview" tab
- No deep-linking to specific tabs required in Phase 4

## Implementation Notes for Executor

1. **Inherit Phase 3 token setup:** `src/index.css` `@theme {}` block is already set by Phase 3. Do not overwrite it. Append only if new tokens are required (no new tokens added in Phase 4).

2. **shadcn `Tabs` usage:** Use `TabsList`, `TabsTrigger`, `TabsContent` from `@/components/ui/tabs`. The default shadcn Tabs style uses a muted background for the list — retain the default, do not override the background color.

3. **LOW CONFIDENCE banner is amber, not destructive:** Use the amber Tailwind utilities listed in the Color section. Do not use `Alert variant="destructive"` — that maps to red and signals an error state, not a confidence calibration. shadcn's `Alert` default variant (no variant prop) renders with the correct neutral structure; apply amber classes manually via `className`.

4. **Exploitation type label casing is locked:** "value-loss trader", "timing-error trader", "directionally-incoherent trader", "archetype-specific overpayer" — always lowercase, always exact. These strings come from the backend API and are rendered verbatim.

5. **Exploitability score co-location is mandatory:** The score number and evidence count must always appear together in the format "Exploitability: {score} | {N} trades". Never render the score in isolation. This applies to the list row, the dossier header, and the Overview tab.

6. **ExploitWindowRow href update:** The Phase 3 `ExploitWindowPanel` `<details>/<summary>` rows need an `href` prop added. The expand/collapse interaction is preserved — the link navigates only when a "View Dossier" link element within the expanded content is clicked, not on summary click (expand/collapse must not navigate).

7. **Table row height:** Minimum 44px per row in the Trade History table — matches touch target requirement. Use `TableRow` with `h-11` class.

8. **Skeleton dimensions for dossier:**
   - Manager name skeleton: `h-7 w-48`
   - Direction + confidence badges row: `h-5 w-64`
   - Exploitability score row: `h-4 w-40`
   - Tab content skeleton cards: `h-24 w-full` per block
   - Trade table skeleton rows: `h-11 w-full` × 5

9. **MIN_TRADE_EVIDENCE_THRESHOLD:** The frontend reads `evidence_count` from the API response and compares it to 10 client-side for the dimming/amber-banner logic. The constant is defined in the backend (`profiling/constants.py`) — do not hardcode `10` directly in JSX; reference a shared constant or read from the API response's `low_confidence` boolean flag if the backend exposes one.
