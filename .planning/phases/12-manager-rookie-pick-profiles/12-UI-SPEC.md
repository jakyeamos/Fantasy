## Interaction Contracts

### "Picks Buyer" badge — ManagerListRow
- Rendered as a `<Badge variant="default">` with label `Picks Buyer` when the manager's `pick_premium_score` is above threshold and evidence is sufficient.
- Uses `--primary` color (cyan) — same as existing exploitability badge treatment.
- Positioned inside the existing `flex items-center gap-2` row alongside the exploitability block, not on a new line.
- When `pick_premium_score` is below threshold or evidence is thin: badge is fully absent (not muted, not disabled — per D-17 silent omission).

### "Rookie & Pick Market" summary card — DossierOverviewTab
- New `<Card>` appended after the existing "Roster Summary" card.
- Contains three data points: positional tendency (e.g., "WR-heavy"), dominant archetype bet (e.g., "Ceiling Bet"), and pick-premium indicator.
- Pick-premium indicator: `<Badge variant="secondary">` using `--accent` (mint) when score is computed; absent when evidence is thin.
- No collapsible behavior; always visible when the Overview tab is active.

### "Draft & Picks" tab — manager dossier
- 4th tab entry in the existing tab bar array.
- Tab button renders only when `show_draft_picks_tab: boolean` flag on the profile API response is `true`.
- When hidden: no placeholder, no empty tab, no lock icon — the tab simply does not appear in the tab bar (per D-02).
- Active tab button uses existing `variant="default"` button style (primary fill).
- Tab content: `DossierDraftPicksTab` component.

### Draft & Picks tab content
- **Primary focal point:** The pick-premium score block is the visual anchor of `DossierDraftPicksTab` — rendered at the top of the tab as a full-width stat-block using `text-xl font-semibold` for the numeric score, establishing hierarchy above the draft history table and archetype patterns below it.
- Per-season draft history: table layout matching `DossierTradeHistoryTab` — `overflow-x-auto rounded-xl border border-border/40`, `bg-card/45` header row.
- Archetype hit patterns: `<Card>` with `CardContent` badge list — each archetype bet displayed as `<Badge variant="default">` using Phase 7 archetype label vocabulary.
- Pick-premium score detail: numeric score in `text-xl font-semibold`, supporting evidence text in `text-sm text-muted-foreground`, same stat-block grid pattern as Roster Summary stat boxes.

### Manager tendency warnings — draft room
- No layout changes to `TendencyWarningList`.
- New manager-specific warnings appear as additional items in the existing warnings array.
- Same `rounded-xl border border-border/45 bg-card/45 p-4` row pattern.
- `warning.title` uses existing `text-sm font-semibold` style; `warning.description` uses `text-sm text-muted-foreground`.

### Loading states
- Use existing `<Skeleton>` for any new data-fetch surface.
- `DossierDraftPicksTab` loading: `<Skeleton className="h-10 w-full" />` repeated 3 times in a `space-y-3` wrapper.
- `RookiePickMarketCard` loading: `<Skeleton className="h-24 w-full" />`.

## Phase-Specific Design Notes

### Evidence-sparse-first design (from CONTEXT.md Specifics)
The expected runtime state is sparse draft evidence. Most managers in a new league will have only startup draft data. The UI contract is built around this expectation:
- The "Draft & Picks" tab is hidden by default; it appears only when evidence clears the threshold (D-02).
- The Overview "Rookie & Pick Market" card and the "Picks Buyer" badge in the manager list are always rendered based on pick-trade transaction signals, which grow with every trade (D-07).
- Startup positional preference IS shown in the Overview card even when the tab is hidden; slot aggression analysis is explicitly excluded with a note when only startup data is present (D-09).

### Accent color discipline
Phase 12 introduces two badge types side by side in `ManagerListRow`:
- Exploitability block: uses `--primary` (cyan) for the score number.
- "Picks Buyer" badge: uses `Badge variant="default"` — also cyan (`--primary`).
- Direction label badge: uses `Badge variant="secondary"` — mint (`--accent`).
- Pick-premium indicator in Overview: uses `Badge variant="secondary"` — mint (`--accent`).

The distinction is intentional: cyan signals exploit/behavioral intelligence; mint signals pick/rookie market tendency. This follows the existing badge variant split already established in the codebase.

### No new layout patterns
Phase 12 does not introduce new page layouts, new routing structures beyond the 4th dossier tab, or new navigation links. All new surfaces live inside the existing dossier page and manager list row. The draft room route gains new warning items via the existing `TendencyWarningList` — no structural change to the draft room layout.
