# Phase 7 — UI Design Contract

> Visual and interaction contract for the Rookie Board & Draft Room phase. Generated by gsd-ui-researcher. Extends Phases 3–6 design contracts — all prior tokens and patterns are inherited.
>
> **Phase 7 introduces two new views:** a tiered rookie board as a nested league route, and a standalone draft room route. Both views are data-dense, analysis-first surfaces — they must communicate opinionated tiers and verdicts at a glance. The tier divider is the primary scan anchor on the board; the trade verdict is the primary scan anchor in the draft room.
>
> **Note on `shadcn_new_init_required: false`:** shadcn/ui was initialized in Phase 3. Phase 7 inherits the existing installation.

## Spacing Scale

Inherited from Phase 3. No new values added.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gaps, inline badge padding, tier divider vertical padding, risk badge internal padding |
| sm | 8px | Compact element spacing — gap between card elements (name, position, archetype, risk badge); gap between draft room answer rows |
| md | 16px | Card internal padding; tier block padding; draft room section internal padding |
| lg | 24px | Tier block bottom margin (space between tier groups); draft room section breaks |
| xl | 32px | Page-level horizontal padding |
| 2xl | 48px | Major section breaks — space between Rookie Board header and first tier; space between draft room entry form and answers panel |
| 3xl | 64px | Reserved — not used in Phase 7 |

Exceptions:
- Touch-target minimum for all interactive elements: 44px tall — inherited from Phase 3
- Tier divider label: minimum 32px tall with `py-2 px-4` padding — this is a scan target, not a compact label
- Draft room verdict banner: minimum 48px tall — the single most important output in the draft room must be visually prominent

## Typography

Inherited from Phases 3–6. No new sizes or weights introduced.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 (regular) | 1.5 |
| Label | 12px | 400 (regular) | 1.4 |
| Heading | 18px | 600 (semibold) | 1.2 |
| Display | 20px | 600 (semibold) | 1.2 |

**Phase 7 usage mapping:**

- **Display (20px / 600):** Tier divider label text (e.g. "Tier 1 — Elite", "Tier 2 — Strong Day 2") — must be visually dominant; this is the primary scan anchor on the rookie board. Also: draft room trade verdict label ("Trade it" / "Use it")
- **Heading (18px / 600):** "Rookie Board" and "Draft Room" page section headers; draft room answer category labels ("Best in Abstract", "League Draft Tendencies", "Trade vs. Use")
- **Body (14px / 400):** Player name on rookie board cards; draft room verdict reasoning string; tendency warning body text; "Available at this slot" slot-availability note under the pick slot selector
- **Label (12px / 400):** Position code, archetype label, and risk band text on rookie board cards; draft room pick identity in entry form; tendency warning detail strings; all secondary metadata

**Weight restriction:** Only 400 and 600. Do not introduce 500 (medium) or 700 (bold).

## Color

Inherited from Phase 3–6 shadcn CSS variable tokens. Two new semantic risk band treatments are added.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `hsl(var(--background))` — near-white/near-black | Page background, rookie board container |
| Secondary (30%) | `hsl(var(--card))` — shadcn card surface | Rookie player cards, draft room answer panels |
| Accent (10%) | `hsl(var(--primary))` — shadcn default blue | Inherited reserved usages from Phases 3–6; see reserved list below |
| Destructive | `hsl(var(--destructive))` — shadcn default red | Not used in Phase 7 — no destructive actions |

**Accent reserved for (Phase 7 additions bolded):**
1. "Snapshot now" button — Phase 3
2. Active/hover state on league card links — Phase 3
3. High confidence badge background — Phase 3
4. Positive delta values in risers list — Phase 3
5. Pick slot projected badge — Phase 6
6. Demand-adjusted value text in trade evaluator — Phase 6
7. **"Enter Draft Room" button on the league drill-in (primary variant)**
8. **Selected pick slot badge in draft room entry form**
9. **"Best in Abstract" top player name — accent-colored to distinguish the system's top pick from the full tier list**

**Risk band colors — new Phase 7 semantic treatment:**

Three mutually exclusive states. Each rookie player card shows exactly one. Rendered as both a text label and a left border tint on the card (satisfies CONTEXT.md D-04).

| Risk Band | Left Border Class | Badge Background | Badge Text | When Applied |
|-----------|-----------------|-----------------|------------|--------------|
| Low | `border-l-4 border-green-500` | `bg-green-50 dark:bg-green-950/20` | `text-green-700 dark:text-green-300` | Floor-safe prospects — low injury history, proven role, high college production efficiency |
| Moderate | `border-l-4 border-amber-400` | `bg-amber-50 dark:bg-amber-950/20` | `text-amber-700 dark:text-amber-300` | Mixed signal prospects — some concern but no disqualifying factor |
| High | `border-l-4 border-red-400` | `bg-red-50 dark:bg-red-950/20` | `text-red-600 dark:text-red-400` | Ceiling-only bets — injury history, size concerns, role uncertainty, or positional devaluation |

**Tier divider label background:**
- `bg-muted` with `text-muted-foreground` — intentionally neutral; the tier label names carry meaning, not color. Only the risk badges on individual cards carry semantic color.

**Draft room verdict banner color:**
- "Trade it" verdict: `bg-amber-100 dark:bg-amber-950/30` with `text-amber-800 dark:text-amber-200` — matches Phase 6 "Sell now" pattern (amber = act on this)
- "Use it" verdict: `bg-green-50 dark:bg-green-950/20` with `text-green-700 dark:text-green-300` — matches Phase 6 "On the clock" pattern (green = deploy)

**League draft tendency warning colors:**
- Positional run warning: `bg-amber-50 dark:bg-amber-950/20` with `text-amber-700 dark:text-amber-300` — same amber family; the user should act on this information
- Value gap alert: `bg-blue-50 dark:bg-blue-950/20` with `text-blue-700 dark:text-blue-300` — matches Phase 6 "Hold" badge; informational, not urgent

**Dark mode:** OS-default via `prefers-color-scheme` — same as Phases 3–6. No mode toggle in Phase 7.

## Component Inventory

### RookieBoardPage (new — nested league route)

**Source:** Custom page composition using shadcn `Card`, `Badge`, `Skeleton`, `Button`, shadcn `Select` (for draft slot filter).

**Route:** `league.$leagueId.rookie-board.tsx` — follows the `league.$leagueId.managers.tsx` nesting pattern (CONTEXT.md D-14, code_context).

**Page structure (top to bottom):**

1. Page header row — `flex items-center justify-between mb-8`
   - "Rookie Board" heading (Heading, 18px/600)
   - League format badge — displays active scoring format abbreviation (e.g. "PPR", "Half PPR", "Superflex") as `Badge variant="secondary"` — confirms which format is active for this board instance
   - "Enter Draft Room" `Button` (variant="default", size="sm") — navigates to `/draft-room?leagueId={leagueId}`

2. Draft slot filter row — `flex items-center gap-2 mb-6`
   - Label: "Highlight available at pick" (Label, 12px/400, `text-muted-foreground`)
   - `Select` (shadcn) with pick slot options populated from `picks` table for this league — "All players" as default (no filter applied)
   - When a slot is selected: players estimated to be available at that slot receive a `bg-primary/10` card background tint; others render at default card surface — this is the repurposed "roster-fit" slot filter per CONTEXT.md D-06

3. Tier groups — one group per tier, rendered in tier order (Tier 1 first)

**TierGroup structure:**

```
[TierDivider — full-width label bar]
[RookieCardGrid — flex-wrap or 2-col grid of RookiePlayerCard]
```

**TierDivider:**
- Full-width `div` with `bg-muted rounded-sm py-2 px-4 mb-4`
- Tier label text (Display, 20px/600, `text-foreground`) — e.g. "Tier 1 — Elite", "Tier 2 — Strong Day 2", "Tier 3 — Day 3 Upside", "Tier 4 — Developmental"
- Tier count (Label, 12px/400, `text-muted-foreground`) appended right-aligned: "{N} players"
- The tier label text is the scan anchor — it must be visually taller and heavier than the player cards below it. The `mb-4` after the divider creates a clear visual pause before the card grid starts.

**Tier vocabulary (Claude's Discretion — CONTEXT.md):**
- Tier 1 — Elite
- Tier 2 — Strong Day 2
- Tier 3 — Day 3 Upside
- Tier 4 — Developmental
- Tier 5 — Flier (used only if the engine produces a 5th tier with low-probability ceiling plays)

**RookieCardGrid:**
- Layout: `grid grid-cols-1 sm:grid-cols-2 lg:grid-cols-3 gap-4`
- Each cell: one `RookiePlayerCard`

### RookiePlayerCard (new)

**Source:** Custom composition using shadcn `Card` variant structure.

**Visual contract:** Left border tint (4px solid) for risk band. Card surface is `hsl(var(--card))` at all times except when the slot filter highlights availability (`bg-primary/10`). The left border is the only structural deviation from a standard shadcn Card.

**Card layout (top to bottom, all within `p-4`):**

1. Name row — `flex items-center justify-between`
   - Player name (Body, 14px/400) — left
   - Position code badge (Label, 12px/400) — `Badge variant="outline"` — right (e.g. "WR", "RB", "QB", "TE")

2. Archetype row — `mt-1`
   - Archetype label text (Label, 12px/400, `text-muted-foreground`) — e.g. "Contested Catch WR", "Early Down Back", "Air Raid WR"
   - Always visible, no expand required — satisfies CONTEXT.md D-03

3. Risk row — `mt-2 flex items-center gap-2`
   - Risk text label (Label, 12px/400) using band-specific color class (see Color section): "Low Risk" / "Moderate Risk" / "High Risk"
   - Risk badge: `rounded px-2 py-0.5 text-xs` + band-specific color classes (see Color section)
   - Both text label AND badge rendered — satisfies CONTEXT.md D-04

4. Slot availability note (conditional) — `mt-2`
   - Renders only when a draft slot filter is active AND this player is estimated to be available at the selected slot
   - Copy: "Available at ~{slot}" (Label, 12px/400, `text-primary`) — e.g. "Available at ~1.06"
   - When a player is NOT estimated to be available, no note renders (card stays at default opacity — do not visually dim unavailable players; that would crowd out tier-scanning)

**Card states:**
- Loading: `Skeleton` covering name row (`h-4 w-32`), archetype row (`h-3 w-48`), risk row (`h-4 w-20`) — 3 skeleton lines, no structural border
- Available-at-slot highlight: `bg-primary/10` card background tint applied on top of `hsl(var(--card))` — left border unchanged
- Default: `hsl(var(--card))` card surface with left border tint per risk band

**Archetype label vocabulary (Claude's Discretion — CONTEXT.md):** Generated by backend engine. Frontend renders verbatim — no client-side mapping.

### DraftRoomPage (new — standalone route)

**Source:** Custom page using shadcn `Card`, `Badge`, `Select`, `Button`, `Alert`, `Skeleton`.

**Route:** `src/routes/draft-room.tsx` — standalone route at `/draft-room` following the `trades.tsx` pattern (CONTEXT.md D-08).

**Entry form (shown on initial load before answers are computed):**

```
[League selector]    [Pick slot selector]    [Analyze button]
```

Layout: `flex items-end gap-4 p-6 bg-card rounded-xl mb-8`

1. League selector — shadcn `Select` with connected league options
   - Label: "League" (Label, 12px/400, `text-muted-foreground`, displayed above the select)
   - Pre-populated if a `leagueId` query param is present (navigated from league drill-in)

2. Pick slot selector — shadcn `Select` with available pick slots for the selected league
   - Label: "Pick slot" (Label, 12px/400, `text-muted-foreground`, displayed above the select)
   - Options populated from `picks` table for the selected league
   - Disabled until a league is selected
   - Default: empty — user must select explicitly

3. "Analyze" `Button` (variant="default", size="default") — triggers draft room computation
   - Disabled until both league and pick slot are selected
   - Loading state: "Analyzing..." label + disabled

**Answers panel (replaces entry form content below; form remains editable above for re-selection):**

The answers panel answers three questions (CONTEXT.md D-07). Rendered as a vertical stack of three answer cards.

```
[VerdictBanner — "Trade it" or "Use it" with one-line reasoning]
[AnswerCard — Best in Abstract]
[AnswerCard — League Draft Tendencies]
```

### VerdictBanner (new — reuses StrategicDistinctionBanner visual pattern)

**Source:** Custom component following the Phase 5 `StrategicDistinctionBanner` visual approach (CONTEXT.md code_context).

Layout: `rounded-xl p-4 flex items-start gap-3` with verdict-specific background color (see Color section).

- Verdict label (Display, 20px/600) — "Trade it" or "Use it" — left-aligned
- One-line reasoning string (Body, 14px/400) — appears on a second line below the verdict label, `text-foreground` (full contrast — this is the most actionable line in the view)
- Vertical stacking: `flex flex-col gap-1`

**Reasoning string examples (not exhaustive — backend returns the string):**
- "Trade it — your 1.04 carries more value than any available prospect here"
- "Use it — Tier 1 talent at this slot; class strength and pick value converge"
- "Trade it — class strength is weak this year; pick capital gains outweigh available prospects"

The reasoning string is rendered verbatim from the API — no client-side transformation.

**Banner placement:** Always renders as the topmost element in the answers panel, before the Best in Abstract card. This is the most important output; it must be seen first.

### AnswerCard — Best in Abstract (new)

**Source:** Custom composition using shadcn `Card`.

Layout: `CardContent p-4`

- Section label (Heading, 18px/600): "Best in Abstract"
- Player name (Display, 20px/600, `text-primary`) — accent-colored per the reserved list above; this is the single recommended player
- Position code + archetype (Label, 12px/400, `text-muted-foreground`) — one line: "WR · Slot Receiver"
- Risk band badge — same badge spec as RookiePlayerCard; single badge, same color rules apply
- Tier label (Label, 12px/400, `text-muted-foreground`) — e.g. "Tier 1 — Elite"

This card gives no ranking list — it surfaces exactly one player. The reasoning for why this player is the top abstract choice is surfaced via the tier label and archetype, not a prose explanation.

### AnswerCard — League Draft Tendencies (new)

**Source:** Custom composition using shadcn `Card` + `Alert`.

Layout: `CardContent p-4 flex flex-col gap-3`

- Section label (Heading, 18px/600): "League Draft Tendencies"
- Tendency warning list — zero to N warnings, each rendered as an `Alert` variant

Two `Alert` variants (using shadcn `Alert` component):
- **Positional run warning** — `variant="default"` with amber color override: `bg-amber-50 dark:bg-amber-950/20 border-amber-300 dark:border-amber-700`
  - Alert icon: Lucide `TrendingUp` (16px, `text-amber-600`)
  - Alert title (Body, 14px/600 — exception: the only 600-weight Body text in Phase 7): position run label, e.g. "WRs go early in this league"
  - Alert description (Label, 12px/400): supporting stat, e.g. "WRs taken 1.2 spots earlier on average vs. system value"
- **Value gap alert** — `variant="default"` with blue color override: `bg-blue-50 dark:bg-blue-950/20 border-blue-300 dark:border-blue-700`
  - Alert icon: Lucide `Info` (16px, `text-blue-600`)
  - Alert title (Body, 14px/600 — same exception as above): player name + gap summary, e.g. "Player X drafted 3 spots early"
  - Alert description (Label, 12px/400): e.g. "System value: 1.06 · Average draft position: 1.03"

Empty state (no warnings): "No significant draft tendency patterns detected for this league yet." (Body, 14px/400, `text-muted-foreground`)

**Note on 600-weight Body exception:** Alert titles within `AnswerCard — League Draft Tendencies` use 14px/600 to create visual hierarchy within the Alert component. This is the only exception to the two-weight rule. All other Body text remains 400.

## Routing Structure

Two new routes introduced in Phase 7.

| Route | Path | Change in Phase 7 |
|-------|------|-------------------|
| Main dashboard | `/` | No change |
| League drill-in | `/league/$leagueId` | "Rookie Board" and "Draft Room" navigation affordances added to the drill-in tabs/nav area |
| Managers list | `/league/$leagueId/managers` | No change |
| Manager dossier | `/league/$leagueId/managers/$managerId` | No change |
| Trade evaluator | `/trades` | No change |
| **Rookie Board** | `/league/$leagueId/rookie-board` | **NEW — nested league route; format recalculates per league** |
| **Draft Room** | `/draft-room` | **NEW — standalone route; league + pick slot selected on entry** |

**Navigation affordances in league drill-in:**
The league drill-in currently uses tabs (Phase 4 pattern). Phase 7 adds two new entries:
- "Rookie Board" tab — navigates to `/league/$leagueId/rookie-board`
- "Draft Room" button — `Button variant="ghost" size="sm"` with Lucide `Clipboard` icon — navigates to `/draft-room?leagueId={leagueId}` (external navigation, not a tab — per CONTEXT.md D-12, draft room is reached from drill-in but is not a nested tab)

**Why Draft Room is not a tab:** Draft room is a standalone decision tool that operates on a pick slot selection — it is not a league view. It is reached from the league drill-in as a launch point, but lives at its own route. A `Button` (not a tab) communicates this distinction.

## Interaction States

Every data region implements all four states (inherited from Phase 3):

| State | Behavior |
|-------|----------|
| Loading | Replace content with matching-height `Skeleton` components; no spinner |
| Success | Render data |
| Empty | Render empty state copy (see Copywriting Contract) |
| Error | Render error state copy inline (no full-page error); TanStack Query retry handles refetch |

**Phase 7 loading states:**

| Context | Loading Behavior |
|---------|-----------------|
| Rookie board tier groups | Show 3 skeleton tier groups: each with a `Skeleton h-8 w-64 mb-4` (tier divider) + 2–3 `Skeleton h-24 w-full rounded-xl` cards |
| Individual RookiePlayerCard | 3 skeleton lines as specified in Component Inventory above |
| Draft room entry → Analyze in-flight | Answers panel region replaced by `Skeleton h-20 w-full` (verdict banner), `Skeleton h-32 w-full` (best in abstract), `Skeleton h-40 w-full` (tendencies); entry form remains interactive for re-selection |
| Draft room tendency warnings | Inside AnswerCard, show `Skeleton h-16 w-full` × 2 while loading |

**Slot filter interaction (rookie board):**
- Selecting a slot from the `Select` triggers a client-side highlight pass — no additional API call if pick board data is already loaded
- "Available at slot" estimation is derived from data already returned by `GET /rookie-board/{league_id}` — each player's response includes an `available_probability_by_slot` map
- If the board data is not yet loaded, the slot filter `Select` is disabled

**Draft room re-analysis:**
- Changing the league or pick slot selector after answers are displayed shows a "Stale — click Analyze to update" inline note (Label, 12px/400, `text-amber-600`) below the "Analyze" button
- Clicking "Analyze" again replaces the answers panel with new loading skeletons then new results

## Implementation Notes for Executor

1. **Two new routes, both additive:** Phase 7 adds `league.$leagueId.rookie-board.tsx` (nested) and `draft-room.tsx` (standalone). No existing routes are modified beyond adding navigation affordances to `league.$leagueId.tsx`.

2. **Tier divider must scan-first:** The tier divider label is the primary scan target on the rookie board. Its `Display` (20px/600) sizing must visually exceed the player card names (Body, 14px/400). The `bg-muted` background creates a full-width bar that reinforces the tier group structure. Do not reduce the tier label to a simple `h3` text line — it must be a full-width pill or bar.

3. **Risk band: both elements always rendered together:** Per CONTEXT.md D-04, risk band is rendered as both a text label ("Low Risk" / "Moderate Risk" / "High Risk") AND a colored badge on the same row. Implementing one without the other violates the design contract.

4. **StrategicDistinctionBanner pattern for VerdictBanner:** The Phase 5 `StrategicDistinctionBanner` component handles the "direct verdict" pattern. VerdictBanner is not a new component from scratch — it follows the same visual layout (colored background, verdict label, reasoning string) but uses different color tokens and Display-sized text. Review the existing component before implementing.

5. **DimensionScoreRow pattern for tendency warnings:** The Phase 5 `DimensionScoreRow` uses an inline reasoning string pattern (label + one-liner). Draft room tendency warnings use a similar label + description pattern but rendered inside shadcn `Alert` instead of a score row. This is different enough to be a new component — do not reuse DimensionScoreRow.

6. **Select component for pick slot:** The shadcn `select` component is new to Phase 7. Install via `npx shadcn@latest add select`. The pick slot selector must be populated from the `picks` table via API — not hardcoded. Available picks for the selected league are fetched from `GET /picks/{league_id}`.

7. **Available-at-slot estimation is backend-computed:** The `available_probability_by_slot` field on each player in the rookie board response is a map of slot → probability. Frontend uses a threshold (e.g. probability >= 0.5 = "available") to determine which players get the highlight tint and slot availability note. The threshold is a named constant in the frontend — `AVAILABILITY_THRESHOLD = 0.5`.

8. **Class strength hook wired in Phase 7:** The `class_strength_signal` field in `GET /picks/{league_id}` was a neutral `0.0` placeholder in Phase 6. Phase 7 replaces this with the actual class evaluation score from the rookie board engine. The draft room's trade verdict reasoning will reference class strength — "class strength is weak this year" is a valid reasoning string from the backend. The frontend renders this verbatim — no frontend-side class strength calculation.

9. **Format badge on rookie board page:** The league format badge (e.g. "PPR", "Superflex") confirms to the user which scoring format is driving the current board's tier assignments. This is a `Badge variant="secondary"` in the page header — not a filter control. The format is fixed for the league; there is no format switcher on the board.

10. **Alert title weight exception:** `Alert` component titles within the AnswerCard — League Draft Tendencies section use `font-semibold` (600) on a 14px base size. This is the only exception to the two-weight-max rule in Phase 7. The shadcn `Alert` component renders its title with `font-medium` by default — override this with `font-semibold` in the custom alert wrapper only in this context.

11. **Draft Room navigation from drill-in is a Button, not a Tab:** The "Enter Draft Room" affordance on the league drill-in is `Button variant="ghost" size="sm"` with a Lucide `Clipboard` icon, placed in the drill-in header or action row — not added to the `Tabs` component. Adding it as a tab would imply draft room content is contained within the league context; it is a standalone decision tool.

12. **Batch fetch pattern for rookie board:** `GET /rookie-board/{league_id}` returns all players for the league's current draft class in a single response, pre-grouped by tier. Do not make per-player or per-tier API calls. TanStack Query `staleTime` of 15 minutes — rookie board data does not change on every page load; it updates when the board is recalculated.
