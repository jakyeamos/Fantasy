# Phase 9 — UI Design Contract

> Visual and interaction contract for the Portfolio & Retrospectives phase. Generated by gsd-ui-researcher. Extends Phases 3–8 design contracts — all prior tokens and patterns are inherited.
>
> **Phase 9 introduces two new scoped additions:**
>
> 1. A top-level **Portfolio route** (`/portfolio`) — the only cross-league view in the app. Contains: a player × league exposure matrix with concentration badges and hedge recommendations, and a correlated NFL team risk section rendered inline with the matrix.
>
> 2. A **Snapshot Comparison panel** added to the existing league drill-in (`/league/$leagueId`) — launched from within the drill-in, showing event-anchored delta diffs across scorecard, direction label, player values, and pick capital.
>
> A **health indicator** ("Last recalibrated: [date]") is added to the Portfolio page footer.
>
> No new shadcn components are required. One new route is added. All design tokens and visual conventions are inherited without change.
>
> **Note on `shadcn_new_init_required: false`:** shadcn/ui was initialized in Phase 3. Phase 9 inherits the existing installation.

## Color

Inherited from Phases 3–8 shadcn CSS variable tokens and semantic color classes. Phase 9 introduces one new semantic treatment: concentration level badges for the exposure matrix.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `hsl(var(--background))` — near-white/near-black | Portfolio page background; league drill-in snapshot comparison panel background |
| Secondary (30%) | `hsl(var(--card))` — shadcn card surface | Portfolio page card containers; matrix surface; snapshot comparison panel surface |
| Accent (10%) | `hsl(var(--primary))` — shadcn default blue | Inherited reserved usages from Phases 3–8; no new Phase 9 additions to this list |
| Destructive | `hsl(var(--destructive))` — shadcn default red | Not used in Phase 9 — no destructive actions |

**Accent reserved for (Phase 9 additions bolded — none new):**
1. "Snapshot now" button — Phase 3
2. Active/hover state on league card links — Phase 3
3. High confidence badge background — Phase 3
4. Positive delta values in risers list — Phase 3
5. Pick slot projected badge — Phase 6
6. Demand-adjusted value text in trade evaluator — Phase 6
7. "Enter Draft Room" button on the league drill-in — Phase 7
8. Selected pick slot badge in draft room entry form — Phase 7
9. "Best in Abstract" top player name in draft room — Phase 7

**Concentration level badge colors — new Phase 9 semantic treatment:**

Three mutually exclusive concentration levels per player row. Each row shows exactly one. Rendered as a `Badge` with level-specific color classes.

| Level | Badge Background | Badge Text | When Applied |
|-------|-----------------|------------|--------------|
| Single (1 league) | `bg-muted` | `text-muted-foreground` | Player appears on exactly 1 connected roster |
| Double (2 leagues) | `bg-amber-50 dark:bg-amber-950/20` | `text-amber-700 dark:text-amber-300` | Player appears on 2 connected rosters — elevated attention warranted |
| Triple+ (3+ leagues) | `bg-red-50 dark:bg-red-950/20` | `text-red-600 dark:text-red-400` | Player appears on 3+ connected rosters — concentration flag active, hedge rec displayed |

**Rationale:** Single → muted (no risk signal); Double → amber (same family as Phase 7 Moderate Risk and Phase 8 Mediocre outcome — cautionary); Triple+ → red (same family as Phase 7 High Risk and Phase 8 Bust outcome). The color vocabulary is consistent across phases.

**Snapshot diff direction colors:**

The delta-forward snapshot diff uses direction colors for each changed field. These reuse the existing Phase 3 risers/fallers palette — no new colors.

| Direction | Color | Example |
|-----------|-------|---------|
| Improved (positive change) | `text-green-700 dark:text-green-300` | "Pick Capital ↑18 pts" |
| Declined (negative change) | `text-red-600 dark:text-red-400` | "WR1 ↓15 pts" |
| Neutral / no change | `text-muted-foreground` | "Direction: unchanged" |
| Direction label changed | `text-foreground` (no color signal — label changes are directionally ambiguous) | "Direction: Productive Struggle → Retool" |

**Correlated team risk flag color:**

Correlated NFL team risk rows are informational — they use the same amber treatment as a Double concentration badge to signal attention without a full red alert.

| Context | Color |
|---------|-------|
| Correlated team risk row (NFL team cluster) | `bg-amber-50 dark:bg-amber-950/20` row background; `text-amber-700 dark:text-amber-300` label text |

**Health indicator color:**

The recalibration health indicator is a muted signal — it confirms recalibration happened, not a warning.

| Context | Color |
|---------|-------|
| "Last recalibrated: [date]" | `text-muted-foreground` (Label, 12px/400) |
| "Not yet recalibrated" | `text-muted-foreground` (same — absence of recalibration is informational, not alarming) |

**Dark mode:** OS-default via `prefers-color-scheme` — same as Phases 3–8. No mode toggle.

## Component Inventory

### Portfolio Page (`/portfolio`)

**Route:** `/portfolio` — top-level nav entry, separate from dashboard and league drill-ins (CONTEXT D-01).

**Page layout:**

```
[Page title "Portfolio" — Display, 20px/600]
[Section: Player Exposure]
  [ExposureMatrix]
  [Correlated Team Risk section — inline below matrix, not a separate section header]
[Portfolio page footer]
  [Health indicator — "Last recalibrated: [date]"]
```

Page container: `p-6 lg:px-8 max-w-5xl mx-auto flex flex-col gap-8` — matches existing page padding conventions from dashboard.

---

#### ExposureMatrix

**Source:** Custom table composition using HTML `<table>` with Tailwind classes. No shadcn Table — the matrix is structurally a spreadsheet-style grid, and the shadcn Table adds overhead unnecessary here (same decision pattern as `RisersFallersList` in Phase 3).

**Structure:** Players are rows. Connected leagues are columns. Concentration badge + hedge rec appear at the end of each player row.

**Header row:** `thead` with player column header (Label, 12px/400, `text-muted-foreground`, "Player") + one `th` per connected league (Label, 12px/400, `text-muted-foreground`, league name truncated to 16 chars with ellipsis). Final `th`: "Exposure" (Label, 12px/400, `text-muted-foreground`).

**Player row layout:** `tr` with alternating `bg-muted/30` on even rows for scannability.

- Player name cell: `td` — player name (Label, 12px/400, `text-foreground`) + position code badge (Label, 12px/400, `Badge variant="outline"`, `text-muted-foreground`) in `flex items-center gap-1`
- League cell (one per connected league): `td` centered — checkmark icon (`Lucide Check`, 14px, `text-green-700 dark:text-green-300`) if player is on that league's roster; empty if not
- Exposure cell: `td` — concentration badge (level-specific color per Color section above) + hedge rec text on the next line if Triple+ (Body, 14px/400, `text-muted-foreground`, italic)

**Hedge rec placement:** Inline below the concentration badge within the same Exposure cell. Hedge rec text is Backend-provided verbatim and rendered without transformation. Example: "Consider trading in your most contending league to reduce exposure." (CONTEXT D-08)

**Row sort order:** Rows sorted by concentration level descending (Triple+ first, then Double, then Single) then alphabetically within each concentration group. This puts the highest-risk rows at the top without requiring user interaction.

**Matrix states:**

| State | Behavior |
|-------|----------|
| Loading | Full table replaced with five `Skeleton h-8 w-full rounded` rows |
| Success | Render matrix |
| Empty | "No players owned across multiple leagues." — Body, 14px/400, `text-muted-foreground`, centered within the matrix container |
| Error | "Portfolio data unavailable. Check that the backend is running, then refresh." — Body, 14px/400, inline |

#### Correlated Team Risk Section

**Placement:** Directly below the `ExposureMatrix` within the Player Exposure card, separated by a `Separator` with `my-4` (16px / `md` token). No separate section header — the correlated risk rows are thematically part of portfolio exposure (CONTEXT D-11).

**Sub-section label:** "Correlated NFL Team Risk" (Label, 12px/400, `text-muted-foreground`, rendered as a row label above the risk rows).

**Risk row layout:** Each detected NFL team cluster renders as one row.

Row: `flex items-start gap-2 rounded-md bg-amber-50 dark:bg-amber-950/20 px-3 py-2`

- Left: Lucide `AlertTriangle` icon (14px, `text-amber-600 dark:text-amber-400`)
- Right: Risk string (Body, 14px/400, `text-amber-700 dark:text-amber-300`) — backend-provided verbatim. Example: "CMC + Deebo + Aiyuk across 2 leagues — one 49ers collapse hits all three." (CONTEXT D-11)

**Correlated risk states:**

| State | Behavior |
|-------|----------|
| Loading | Two `Skeleton h-10 w-full rounded` rows |
| Success | Render risk rows |
| Empty | "No correlated NFL team clusters detected." — Label, 12px/400, `text-muted-foreground` |
| Error | "Correlated risk data unavailable. Check that the backend is running, then refresh." — Label, 12px/400, `text-muted-foreground`, inline |

#### Portfolio Page Footer (Health Indicator)

### Snapshot Comparison Panel (league drill-in extension)

**Route:** Extends `/league/$leagueId` — not a new route (CONTEXT D-02).

**Entry point:** A "Compare to snapshot" `Button` (variant="outline", size="sm") added to the league drill-in header row alongside the existing "Snapshot now" button. Clicking opens the panel.

**Panel implementation:** Uses the existing shadcn `Sheet` component (already installed in Phase 5) — slides in from the right. Width: `sm:max-w-lg` (standard Sheet width from Phase 5). This avoids a new full-page route while giving adequate horizontal space for the delta display.

**Sheet structure:**

```
[SheetHeader]
  [SheetTitle: "Compare to Snapshot" — Heading, 18px/600]
  [SheetDescription: "Select a snapshot anchor to see what changed." — Body, 14px/400, text-muted-foreground]
[SheetContent]
  [Anchor selector row]
  [SnapshotDiffView — conditional on anchor selection]
[SheetFooter — empty; no confirm/cancel actions needed]
```

---

#### Anchor Selector Row

**Layout:** `flex items-center gap-3`

- Label: "Compare from" (Label, 12px/400, `text-muted-foreground`)
- `Select` component (already installed): displays available event-anchored labels. Options populated from backend. Example options: "Start of season", "End of season", "After Kelce trade (Feb 14)", "After 3-player roster change (Jan 8)". (CONTEXT D-04)
- Default state: placeholder text "Select a snapshot..." — no diff renders until an anchor is selected

Anchor option text format: "{event type} ({date})" — e.g. "Trade — Feb 14, 2026" or "Season start — Sep 3, 2025". The backend provides the formatted label string verbatim; the frontend renders without transformation.

Anchor selector loading state: `Skeleton h-9 w-56 rounded` replacing the Select while anchor list loads.

---

#### SnapshotDiffView

Renders below the anchor selector row when an anchor is selected. Conditionally mounted — not rendered before anchor selection.

**Layout:** `flex flex-col gap-2 mt-4`

**Section label:** "What changed since {anchor label}" (Body, 14px/400, `text-muted-foreground`) — anchor label interpolated from the selected option text.

Each changed field renders as one diff row. Fields are sorted by magnitude of change descending — largest absolute delta first (CONTEXT discretion). Unchanged fields are not shown.

**DiffRow layout:** `flex items-center justify-between py-1`

- Left: Field label (Label, 12px/400, `text-muted-foreground`) — e.g. "Direction", "Pick Capital", "WR1", "RB2"
- Right: Delta string (Body, 14px/400) with direction color (see Color section):
  - Numeric delta: "↑18 pts" in `text-green-700` or "↓15 pts" in `text-red-600`
  - Direction label change: "Productive Struggle → Retool" in `text-foreground`
  - Player departed since snapshot: "Traded (was WR2)" in `text-muted-foreground` — italic
  - Player added since snapshot: "+ DeAndre Hopkins added" in `text-green-700 dark:text-green-300`

**Pick capital diff:** Uses Phase 6 `capital_score` value — displayed as "↑18 pts" or "↓22 pts", not as a pick list diff. (CONTEXT D-07)

**Players who left the roster:** Still appear in the diff with "Traded" or "Dropped" label per CONTEXT D-06. These rows render below active player diffs, in order of their absolute value change at the time of the snapshot.

**SnapshotDiffView states:**

| State | Behavior |
|-------|----------|
| Pre-selection | Not rendered (no anchor selected yet) |
| Loading (anchor selected, diff loading) | Five `Skeleton h-6 w-full rounded` rows |
| Success | Render diff rows |
| Empty (no changes detected) | "No changes detected since this snapshot." — Body, 14px/400, `text-muted-foreground`, centered |
| Error | "Snapshot comparison unavailable. Check that the backend is running, then refresh." — Body, 14px/400, inline |

## Interaction States

Every data region implements all four states (inherited from Phase 3):

| State | Behavior |
|-------|----------|
| Loading | Replace content with matching-height `Skeleton` components; no spinner |
| Success | Render data |
| Empty | Render empty state copy (see Copywriting Contract) |
| Error | Render error state copy inline; TanStack Query retry handles refetch |

**Phase 9 loading states:**

| Context | Loading Behavior |
|---------|-----------------|
| Portfolio page initial load (matrix + correlated risk) | Five `Skeleton h-8 w-full rounded` rows for matrix; two `Skeleton h-10 w-full rounded` rows for correlated risk section |
| Snapshot anchor list loading | `Skeleton h-9 w-56 rounded` replacing the Select |
| Snapshot diff loading (after anchor selected) | Five `Skeleton h-6 w-full rounded` rows |
| Portfolio health indicator loading | `Skeleton h-4 w-48 rounded` replacing the timestamp |

**TanStack Query stale times:**

- Portfolio exposure matrix: `staleTime: 5 * 60 * 1000` (5 minutes) — exposure data changes on ingest; short stale time ensures fresh view after roster changes
- Snapshot anchor list: `staleTime: 60 * 1000` (1 minute) — anchors are written on trade/roster events; near-fresh
- Snapshot diff: `staleTime: 5 * 60 * 1000` (5 minutes) — diff is point-in-time, safe to cache briefly
- Health indicator (recalibration date): `staleTime: 60 * 60 * 1000` (1 hour) — recalibration is post-season; near-static

## Implementation Notes for Executor

1. **Portfolio route is a new top-level route — add it to nav.** Create `src/routes/portfolio.tsx`. Add a `<Link to="/portfolio">` entry to the app nav alongside the existing dashboard link. Use TanStack Router `<Link>` with `data-[active=true]:text-primary` for active state styling.

2. **ExposureMatrix is an HTML `<table>`, not shadcn Table.** The matrix is a spreadsheet-style grid where column count varies by number of connected leagues. shadcn Table adds unnecessary Radix overhead for this layout. Use plain `<table>` with Tailwind classes, consistent with the `RisersFallersList` decision in Phase 3.

3. **Snapshot comparison opens in a Sheet, not a new route.** The `Sheet` component (already installed from Phase 5) slides in from the right. The league drill-in does not navigate away — the Sheet overlays it. Trigger: `Button variant="outline" size="sm"` labeled "Compare to snapshot" in the drill-in header row alongside the existing "Snapshot now" button.

4. **Anchor labels are verbatim from backend — do not parse or reformat.** The backend returns event-anchored labels as pre-formatted strings (e.g. "Trade — Feb 14, 2026"). The frontend renders these in the `Select` options without transformation. The diff section header interpolates the selected label directly: "What changed since {anchor label}."

5. **Diff rows sorted by absolute delta magnitude descending.** Compute sort client-side from the backend-provided delta values. Direction label changes (no numeric delta) sort after numeric delta rows. Departed player rows sort last.

6. **Pick capital diff uses Phase 6 `capital_score` — not a raw pick list.** The diff row for pick capital shows "↑18 pts" or "↓22 pts" based on the Phase 6 `capital_score` output, not a count of picks added or removed. If pick capital is unchanged, the row is omitted from the diff.

7. **Departed players still appear in the diff.** Players who were on the roster at the snapshot but have since been traded or dropped appear at the bottom of the diff with their departure type ("Traded" / "Dropped") and their value change since the snapshot in `text-muted-foreground` italic. The backend provides both the departure type and the value delta.

8. **Correlated team risk rows are amber, not red.** Correlated NFL team risk is an informational signal — it does not trigger the full red concentration treatment. Use `bg-amber-50 dark:bg-amber-950/20` row background and `text-amber-700 dark:text-amber-300` text. The `AlertTriangle` Lucide icon (already bundled) is used as the leading icon on each risk row.

9. **Health indicator placement is Portfolio page footer.** The "Last recalibrated: [date]" indicator lives at the bottom of the Portfolio page in a right-aligned footer row (`flex items-center justify-end pt-4 border-t mt-8`). It is passive — no badge, no icon, no CTA. Per CONTEXT D-14, the value is confirmation that recalibration happened, not a model accuracy report.

10. **Concentration badge text uses numeric count for 3+.** The badge for Triple+ shows the actual count (e.g., "3 leagues", "4 leagues") — not a static "3+" string. The backend provides the count; the frontend interpolates. Double badge is always "2 leagues." Single badge is always "1 league." This ensures the badge is informative for users with many connected leagues.

11. **Hedge rec text is verbatim from backend.** The hedge recommendation string (CONTEXT D-08) is provided by the backend and rendered without client-side transformation. It appears on a second line within the Exposure cell, below the concentration badge, in Body (14px/400) `text-muted-foreground` italic. Only Triple+ rows display a hedge rec — Single and Double rows do not.

12. **Matrix rows sorted by concentration level descending.** Triple+ rows appear first, Double rows second, Single rows last. Within each concentration group, rows are sorted alphabetically by player name. This sort is applied client-side after the backend returns the exposure data — no server-side sort parameter is needed.

13. **No new Lucide icons beyond AlertTriangle.** Phase 9 uses only the `AlertTriangle` icon for correlated team risk rows and the existing `Check` icon for the exposure matrix presence cells. Both are already bundled with shadcn/ui — no new icon import required.

14. **"Large roster change" auto-labeling threshold is 3+ player changes in one ingest.** Per CONTEXT (Claude's Discretion), a snapshot anchor is auto-labeled for a roster change event when 3 or more players change in a single ingest run. This threshold is a named constant `SNAPSHOT_ROSTER_CHANGE_THRESHOLD = 3` in the backend portfolio constants file — not a magic number.
