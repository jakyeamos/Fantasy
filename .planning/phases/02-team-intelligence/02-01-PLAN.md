  <files>backend/src/fantasy/intelligence/scorecard_engine.py</files>
  <action>
    Create `backend/src/fantasy/intelligence/scorecard_engine.py` implementing `ScorecardEngine` with the following contract:

    ```python
    class ScorecardEngine:
        def __init__(self, conn: duckdb.DuckDBPyConnection): ...
        def compute(self, league_id: str, roster_id: int) -> TeamScorecard: ...
        def compute_all(self, league_id: str) -> dict[int, TeamScorecard]: ...
        def _gather_inputs(self, league_id: str, roster_id: int) -> ScorecardInputs: ...
        def _apply_corrections(self, inputs: ScorecardInputs, league_id: str, roster_id: int) -> ScorecardInputs: ...
        def _score_win_now(self, inputs: ScorecardInputs, all_inputs: dict[int, ScorecardInputs]) -> float: ...
        # ... 8 more _score_* methods, each returning a raw float (unnormalized)
    ```

    Key implementation requirements:

    1. `_gather_inputs()` must parse JSON columns with json.loads() — never assume starters/players/reserve/taxi are Python lists from DuckDB (they are VARCHAR). Handle None values: `json.loads(row or "[]")`.

    2. `_score_pick_capital()` must implement the dual-query pattern from RESEARCH.md Code Examples exactly: traded picks where owner_id=this_roster_id PLUS untouched original picks (future seasons × rounds minus traded-away set). Use ROUND_WEIGHTS from constants.

    3. `_apply_corrections()` must query the `corrections` table for entity_type='player' or 'roster' corrections relevant to this team before any sub-score computation. Corrected values override raw ingested values.

    4. `compute_all()` must normalize sub-scores league-relatively: gather raw scores for ALL rosters in the league, then apply `normalize_within_league()` to each sub-score dimension. The returned TeamScorecard objects have normalized (0.0-1.0) values. `compute()` for a single roster must call `compute_all()` internally and return the one relevant result — never normalize against just one team.

    5. Missing player stats: if a player has no rows in `player_stats_weekly` for any recent season, use `adp_rank` from `player_adp_baseline` as a proxy (lower adp_rank = better = higher score). If also missing from ADP, use the league median fantasy points for their position. Document the fallback with a comment.

    6. Fragility sub-score: use `games_played / total_possible_games` (season weeks) as the availability proxy, averaged across starters. Concentration (HHI of fantasy_points) also factors in — high concentration = high fragility. Blend 50/50: `fragility_raw = 0.5 * (1 - avg_availability) + 0.5 * hhi_normalized`. Note in a comment that fragility reflects availability + concentration, not diagnosed injury risk.

    7. Positional insulation: for each starting roster slot required by the league (from `leagues.settings`), check whether the bench has at least one player at the same position. Score = fraction of starting positions with a bench backup. Query `leagues` table for roster_positions to determine required slots.

    Do NOT implement persistence to `team_scorecards` table here — that is the IntelligenceService's responsibility (Plan 04).
  </action>
