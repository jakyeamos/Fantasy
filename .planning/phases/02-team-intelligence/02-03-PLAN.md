Context inputs to compute_player():
- `direction_label: str` — the team's current direction (from DirectionEngine output)
- `roster_id: int` — the team owning this player (needed for team-fit and direction lenses)

Constants to use (from constants.py):
- DIRECTION_VALUE_WEIGHTS: 12 component weights per direction label
- FORMAT_MULTIPLIERS: PPR/superflex/TEP multipliers
- POSITIONAL_PEAK_AGE, POSITIONAL_CLIFF_AGE: for age_curve component

Component → Lens mapping (from RESEARCH.md Pattern 4):
- lens_production = avg(comp_production, comp_short_term, comp_ceiling, comp_floor) — equal weight
- lens_market = avg(comp_market_liquidity, comp_positional_scarcity, comp_rerollability)
- lens_insulation = avg(comp_insulation, comp_role_stability, 1-comp_fragility, comp_contract)
- lens_team_fit = avg(comp_positional_scarcity, comp_role_stability) — league-specific positional scarcity
- lens_direction = dot(all 12 components, DIRECTION_VALUE_WEIGHTS[direction_label]) — clamped to [0.0, 1.0]

Missing stats fallback (RESEARCH.md Pitfall 2):
- comp_production: if no player_stats_weekly rows → use 1 - (adp_rank / max_adp_rank_in_league), where lower ADP rank = more valuable
- comp_short_term: same ADP proxy
- If also missing from ADP: use 0.4 (slightly below league median) with a comment explaining the fallback

    Private methods for each component (each returns float in [0.0, 1.0]):
    ```
    _comp_production(player_id, league_id, season) -> float
    _comp_short_term(player_id, league_id) -> float
    _comp_role_stability(player_id, league_id) -> float
    _comp_age_curve(player_id, position, age) -> float
    _comp_insulation(player_id, league_id) -> float
    _comp_market_liquidity(player_id, league_id) -> float
    _comp_positional_scarcity(position, league_id) -> float
    _comp_fragility(player_id, league_id, season) -> float
    _comp_ceiling(player_id, league_id, season) -> float
    _comp_floor(player_id, league_id, season) -> float
    _comp_rerollability(player_id, league_id) -> float
    _comp_contract(player_id) -> float   # proxy: 0.5 for all players (no contract data in dynasty); document this
    ```

    Aggregation methods:
    ```
    _aggregate_lenses(components: dict[str, float | None], direction_label: str, league_format: dict) -> dict[str, float]
    _apply_format_multipliers(lens_production: float, position: str, league_format: dict) -> float
    ```

    Key implementation requirements:

    1. `_comp_age_curve()`: Use POSITIONAL_PEAK_AGE and POSITIONAL_CLIFF_AGE. Score formula:
       - age < peak_age: `1.0 - (age / peak_age) * 0.3` (young players score 0.7-1.0 — upside credit)
       - peak_age <= age < cliff_age: linearly interpolate from 0.7 down to 0.1
       - age >= cliff_age: 0.0 (maximum age risk, so age_curve = 0.0 = high risk in the direction lens)
       Note: high comp_age_curve = good for rebuild direction (youth upside). The DIRECTION_VALUE_WEIGHTS handles the sign correctly.

    2. `_comp_market_liquidity()`: Count how many transactions in the league have involved this player in the last 2 seasons (from `transactions` table, parsing adds/drops JSON). Normalize by total transactions in the league. Higher transaction frequency = more liquid = higher score.

    3. `_comp_positional_scarcity()`: Count how many players at this position are rostered across the league (from `rosters`). Fewer rostered players at the position = scarcer = higher score. Normalize within league.

    4. `_comp_contract()`: Return 0.5 for all players with a code comment: "No contract data in dynasty Sleeper leagues. Proxy: 0.5 neutral. Phase 8 may enrich with NFL contract years remaining."

    5. `_apply_format_multipliers()`: Read the league's ppr value (0, 0.5, 1.0) and superflex/tep flags from the `leagues` table. Apply FORMAT_MULTIPLIERS from constants.py. Clamp result to [0.0, 1.0] after applying multipliers.

    6. `lens_direction` computation: weighted dot product of all 12 component values using DIRECTION_VALUE_WEIGHTS[direction_label]. Components are treated as 0.5 when None. Clamp output to [0.0, 1.0].

    7. All lens_* fields must always be float (never None). When component inputs are None, use 0.5 as the fallback value for that component in lens calculations. Comment this behavior.

    Do NOT persist results to `player_values` table — that is IntelligenceService's responsibility (Plan 04).
