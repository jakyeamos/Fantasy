Reads from constants.py:
- DIRECTION_WEIGHTS: dict[str, dict[str, float]] — 8 labels × sub-score weights
- DIRECTION_MOVE_MATRIX: dict[str, dict[str, list[str]]] — approved/discouraged per label
- MOVE_TYPE_TARGETS: dict[str, str] — move_type → sub-score it addresses

No DuckDB access needed — DirectionEngine is a pure-Python computation on a TeamScorecard. It is stateless and has no DB dependency. This is intentional and testable without any database fixture.

Classification algorithm (from RESEARCH.md Pattern 2):
1. For each of the 8 direction labels, compute: label_score = sum(scores[dim] * weight for dim, weight in DIRECTION_WEIGHTS[label].items())
2. Rank by label_score descending
3. primary_label = ranked[0][0]
4. confidence = (top_score - second_score) / (max_score - min_score + 1e-9), clamped to [0.0, 1.0]
5. alternates = all labels with score >= primary_score * 0.85, minimum 2 entries regardless of threshold
6. delta = which sub-score change of what magnitude flips primary to ranked[1]
7. reasoning = human-readable string: "Team scores high in {top 3 contributing dims} → primary signal for {label}"

Move ranking algorithm (from RESEARCH.md Pattern 6):
- approved = DIRECTION_MOVE_MATRIX[label]["approved"]
- rank by sub-score gap size: moves addressing the team's weakest dimensions rank first
- MOVE_TYPE_TARGETS maps move_type → which sub-score it addresses

    ```python
    class DirectionEngine:
        def classify(self, scorecard: TeamScorecard) -> DirectionResult: ...
        def rank_moves(self, direction_label: str, scorecard: TeamScorecard) -> list[str]: ...
        def _compute_label_scores(self, scores: dict[str, float]) -> dict[str, float]: ...
        def _compute_confidence(self, label_scores: dict[str, float]) -> float: ...
        def _compute_alternates(self, ranked: list[tuple], primary_score: float) -> list[dict]: ...
        def _compute_delta(self, scores: dict[str, float], ranked: list[tuple]) -> dict: ...
        def _build_reasoning(self, label: str, scores: dict[str, float], label_score: float) -> str: ...
    ```

    Critical contract details:

    1. `_compute_alternates()`: Always return at least 2 alternates. If fewer than 2 labels score >= primary_score * 0.85, include the next-highest labels until alternates has at least 2 entries. Each alternate entry: `{"label": str, "score": float, "gap": float}`.

    2. `_compute_confidence()`: Use the formula from RESEARCH.md Code Examples. When all labels score equally (span < 1e-9), return 0.0. When confidence < 0.10, the reasoning string returned by classify() must begin with "Low confidence —".

    3. `_compute_delta()`: Find the sub-score dimension where a change of the smallest magnitude would flip the primary label to ranked[1][0]. Return `{"flip_to": str, "dimension": str, "change_needed": float, "direction": "increase" | "decrease"}`. Compute by incrementally adjusting each sub-score by 0.05 and checking if ranked[1] would then outscore ranked[0].

    4. `_build_reasoning()`: Build a string of the form: "Primary signal: {top 2-3 contributing sub-score dimension names} are {high/low}. {label} teams typically {one sentence of context}." The context sentence is a hardcoded string per label in the method body (not a separate constant). Keep it factual: "true_contender" → "True contender teams have high win-now production with roster depth to back it up." etc.

    5. `rank_moves()`: approved = DIRECTION_MOVE_MATRIX[direction_label]["approved"]. Sort by the score of the sub-score dimension each move targets (MOVE_TYPE_TARGETS), using a HIGH score for moves addressing a LOW-scoring dimension (most urgent gap) and a LOW priority for moves addressing an already-strong dimension. If a move type is not in MOVE_TYPE_TARGETS, assign neutral priority (0.5). Return ordered list, most urgent first.

    No database dependency. No FastAPI dependency. No import from routers.
