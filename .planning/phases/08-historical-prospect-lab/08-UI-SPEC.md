# Phase 8 — UI Design Contract

> Visual and interaction contract for the Historical Prospect Lab phase. Generated by gsd-ui-researcher. Extends Phases 3–7 design contracts — all prior tokens and patterns are inherited.
>
> **Phase 8 introduces no new routes.** All outputs layer onto the existing Phase 7 `RookiePlayerCard` component and rookie board page. The `RookiePlayerCard` gains three new data regions: historical comps (three named comps), a hit-rate bucket badge, and an over/undervalue flag with expandable per-signal sub-flags. No new shadcn components are required. No new design tokens are introduced.
>
> **Note on `shadcn_new_init_required: false`:** shadcn/ui was initialized in Phase 3. Phase 8 inherits the existing installation. No new components to install.

## Typography

Inherited from Phases 3–7. No new sizes or weights introduced.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 (regular) | 1.5 |
| Label | 12px | 400 (regular) | 1.4 |
| Heading | 18px | 600 (semibold) | 1.2 |
| Display | 20px | 600 (semibold) | 1.2 |

**Phase 8 usage mapping:**

- **Body (14px / 400):** Comp match reason string on each comp row (e.g. "similar draft capital, age, and target share profile"); over/undervalue net verdict inline label on card (e.g. "8 spots overvalued"); sub-flag direction + magnitude string in expanded panel (e.g. "Age: 0.5 years older than median — slight negative")
- **Label (12px / 400):** Section header label "Historical Comps" and "Model Signal"; comp player name (de-emphasized — the reason string carries more meaning than the name); outcome bucket badge text; hit-rate bucket label; "low confidence" tag text; section role labels within the expanded sub-flags panel (e.g. "Draft Capital", "Age", "Production")
- **Heading (18px / 600):** Not introduced in new Phase 8 elements — section labels within the card use Label (12px) to keep the card compact
- **Display (20px / 600):** Not used in Phase 8 card extensions — card extensions are data rows, not primary scan targets

**Weight restriction:** Only 400 and 600. The Alert title exception from Phase 7 (14px/600) does not apply to Phase 8 additions. No new weight exceptions.

## Color

Inherited from Phase 3–7 shadcn CSS variable tokens and semantic color classes. Phase 8 introduces one new semantic treatment: outcome bucket badge colors for hit/mediocre/bust.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `hsl(var(--background))` — near-white/near-black | Page background, rookie board container (unchanged) |
| Secondary (30%) | `hsl(var(--card))` — shadcn card surface | Rookie player cards, all Phase 8 expanded panels inside cards |
| Accent (10%) | `hsl(var(--primary))` — shadcn default blue | Inherited reserved usages from Phases 3–7; no new Phase 8 additions to this list |
| Destructive | `hsl(var(--destructive))` — shadcn default red | Not used in Phase 8 — no destructive actions |

**Accent reserved for (Phase 8 additions bolded — none new):**
1. "Snapshot now" button — Phase 3
2. Active/hover state on league card links — Phase 3
3. High confidence badge background — Phase 3
4. Positive delta values in risers list — Phase 3
5. Pick slot projected badge — Phase 6
6. Demand-adjusted value text in trade evaluator — Phase 6
7. "Enter Draft Room" button on the league drill-in — Phase 7
8. Selected pick slot badge in draft room entry form — Phase 7
9. "Best in Abstract" top player name in draft room — Phase 7

**Outcome bucket colors — new Phase 8 semantic treatment:**

Three mutually exclusive outcome buckets per comp. Each comp row shows exactly one. Rendered as a `Badge` with bucket-specific color classes.

| Outcome | Badge Background | Badge Text | When Applied |
|---------|-----------------|------------|--------------|
| Hit | `bg-green-50 dark:bg-green-950/20` | `text-green-700 dark:text-green-300` | Player met the position-specific hit threshold for N seasons |
| Mediocre | `bg-amber-50 dark:bg-amber-950/20` | `text-amber-700 dark:text-amber-300` | Player produced but did not reach hit threshold; neither a hit nor a bust |
| Bust | `bg-red-50 dark:bg-red-950/20` | `text-red-600 dark:text-red-400` | Player failed to reach mediocre band — career production below positional threshold |

**Rationale:** Hit → green (same family as Phase 7 Low Risk); Bust → red (same family as Phase 7 High Risk); Mediocre → amber (same family as Phase 7 Moderate Risk). The families are consistent — the user's mental model from risk bands transfers to outcome buckets without a new color vocabulary.

**Hit-rate bucket badge colors:**

Hit-rate bucket is a summary confidence signal per prospect, not a per-comp signal. It conveys "players like this historically hit at X% rate."

| Bucket | Badge Variant | Notes |
|--------|--------------|-------|
| High hit rate (top tier) | `Badge variant="default"` with `bg-green-50 dark:bg-green-950/20 text-green-700 dark:text-green-300` | Same as hit outcome — bucket communicates favorable base rate |
| Moderate hit rate | `Badge variant="default"` with `bg-amber-50 dark:bg-amber-950/20 text-amber-700 dark:text-amber-300` | Same as mediocre outcome — cautionary base rate |
| Low hit rate | `Badge variant="default"` with `bg-red-50 dark:bg-red-950/20 text-red-600 dark:text-red-400` | Same as bust outcome — unfavorable base rate |

**Over/undervalue flag inline color:**

The net verdict appears inline on the closed card. Direction drives color — not a third semantic category.

| Direction | Color | Example |
|-----------|-------|---------|
| Overvalued | `text-red-600 dark:text-red-400` | "8 spots overvalued" |
| Undervalued | `text-green-700 dark:text-green-300` | "3 spots undervalued" |
| Low confidence | `text-muted-foreground` | "Insufficient comps — low confidence" |

**Sub-flag direction colors (expanded panel only):**

Each sub-flag shows a direction indicator within the expanded over/undervalue section.

| Direction | Color |
|-----------|-------|
| Negative signal | `text-red-600 dark:text-red-400` |
| Positive signal | `text-green-700 dark:text-green-300` |
| Neutral / not significant | `text-muted-foreground` |

**Dark mode:** OS-default via `prefers-color-scheme` — same as Phases 3–7. No mode toggle.

### RookiePlayerCard (extended — Phase 7 base, Phase 8 additions)

Phase 8 adds three new data regions to the existing `RookiePlayerCard` layout below the existing risk row. The card's existing structure (name row, archetype row, risk row, slot availability note) is unchanged.

**Extended card layout (additions below existing rows, all within existing `p-4`):**

```

[Archetype row]         ← Phase 7 (unchanged)
```

The `shadcn Separator` component (already installed) renders the divider between Phase 7 content and Phase 8 content. Use `my-2` margin — 8px top and bottom (`sm` token).

---

#### New Region 1: Hit-Rate + Model Row

Layout: `flex items-center justify-between mt-2`

Left: Section label "Model Signal" (Label, 12px/400, `text-muted-foreground`)

Right: Hit-rate bucket badge
- Text: backend-provided bucket string, e.g. "High hit rate" / "Moderate hit rate" / "Low hit rate"
- Rendered as `Badge` with bucket-specific color (see Color section above)
- Typography: Label (12px/400) inside badge — `rounded px-2 py-0.5 text-xs`

If hit-rate is below minimum comp count threshold, badge renders as `Badge variant="outline"` with text: "Low confidence" — `text-muted-foreground` color (muted, not green/amber/red — insufficient evidence is a distinct state from a bucket assignment).

---

#### New Region 2: Over/Undervalue Flag

Layout: `mt-2 flex items-center justify-between`

Left: Net verdict string (Body, 14px/400) with direction-specific color (see Color section)
- Overvalued example: "8 spots overvalued" in `text-red-600 dark:text-red-400`
- Undervalued example: "3 spots undervalued" in `text-green-700 dark:text-green-300`
- Low confidence: "Insufficient comps — low confidence" in `text-muted-foreground`

Right: Expand toggle — Lucide `ChevronDown` icon (16px, `text-muted-foreground`) — rotates to `ChevronUp` when panel is open. Minimum touch target: 32px × 32px (`p-2` wrapper around icon).

**Expanded sub-flags panel** (renders below the net verdict row when toggle is open):

Layout: `mt-2 rounded-md bg-muted/50 p-3 flex flex-col gap-2`

Each sub-flag row: `flex items-center justify-between`
- Left: Signal label (Label, 12px/400, `text-muted-foreground`) — e.g. "Draft Capital", "Age", "Production", "Market Share", "Athletic Testing"
- Right: Direction + magnitude string (Body, 14px/400) with direction-specific color — e.g. "0.5 years older — slight negative" (red), "top-10% market share — strong positive" (green), "within normal range" (muted)

The backend returns the sub-flag strings verbatim. Frontend renders them without transformation.

**Expand/collapse animation:** CSS `transition-all duration-150` on the panel container — fast enough to feel responsive, slow enough to not feel like a flash. No spring animations.

**Keyboard accessibility:** Toggle button must be a `<button>` element (not a `div`) with `aria-expanded` state and `aria-controls` pointing to the sub-flags panel id. Focus ring: `focus-visible:ring-2 focus-visible:ring-ring focus-visible:ring-offset-2`.

#### New Region 3: Historical Comps

Layout: `mt-2 flex flex-col gap-2`

Section label row: `flex items-center justify-between mb-1`
- Left: "Historical Comps" (Label, 12px/400, `text-muted-foreground`)
- Right: ADP tier context string (Label, 12px/400, `text-muted-foreground`) — e.g. "at this draft capital tier" — reminds the user that ceiling/floor are tier-relative per CONTEXT.md D-05

Three comp rows rendered in order: ceiling comp first, median comp second, floor comp third.

**CompRow layout:** `flex items-start gap-2`

Left column (fixed width `w-16`):
- Comp role badge: `Badge variant="outline"` with compact text (Label, 12px/400)
  - "Ceiling" — `text-green-700 dark:text-green-300 border-green-500`
  - "Median" — `text-muted-foreground border-muted-foreground`
  - "Floor" — `text-red-600 dark:text-red-400 border-red-400`
- Below comp role badge: outcome bucket badge (Label, 12px/400) with bucket color (hit/mediocre/bust — see Color section)

Right column (flex-1):
- Player name (Label, 12px/400, `text-foreground`) — name alone, no position code — e.g. "Justin Jefferson"
- Match reason string (Body, 14px/400, `text-muted-foreground`, `leading-tight`) — one line — e.g. "similar draft capital, age, and target share profile" — rendered verbatim from backend

**Comp section loading state:** Three `CompRow` skeletons:
- Each skeleton: `Skeleton h-4 w-16` (left column) + `Skeleton h-8 w-full rounded` (right column, two lines approximated)

**Comp section empty state:** "No historical comps available for this prospect." (Label, 12px/400, `text-muted-foreground`)

### Rookie Board Sort Controls (extended)

Per CONTEXT.md D-14, the rookie board is data-forward and sortable by model fields. Phase 8 adds sortable columns to the existing board. The sort controls are added to the board's filter row (existing `flex items-center gap-2` row that houses the slot filter from Phase 7).

**Sort control addition:** A second `Select` component (already installed) added to the filter row.
- Label: "Sort by" (Label, 12px/400, `text-muted-foreground`)
- Options:
  - "Tier (default)" — default sort; renders tier groups in tier order
  - "ADP Divergence" — sorts all players by ADP divergence magnitude descending (most overvalued or undervalued first, regardless of tier)
  - "Hit Rate" — sorts all players by hit-rate bucket descending (High first, then Moderate, then Low)
- When "ADP Divergence" or "Hit Rate" is selected: tier group dividers are hidden; the board renders as a flat sorted list with position code badges serving as the visual grouping signal
- When "Tier (default)" is selected: tier group dividers are shown; standard Phase 7 tier view restored

**Sort state persistence:** Sort selection persists for the current session via React state — not in URL params, not in localStorage. Navigating away and back resets to "Tier (default)."

## Interaction States

Every data region implements all four states (inherited from Phase 3):

| State | Behavior |
|-------|----------|
| Loading | Replace content with matching-height `Skeleton` components; no spinner |
| Success | Render data |
| Empty | Render empty state copy (see Copywriting Contract) |
| Error | Render error state copy inline; TanStack Query retry handles refetch |

**Phase 8 loading states:**

| Context | Loading Behavior |
|---------|-----------------|
| Phase 8 card regions loading (model outputs not yet fetched) | Hit-rate row: `Skeleton h-4 w-24`; Over/undervalue row: `Skeleton h-4 w-32`; Comps section: three `CompRow` skeletons per spec above |
| Sort by ADP Divergence selected, data loading | Flat list of `Skeleton h-24 w-full rounded-xl` cards (no tier dividers during load) |
| Sub-flags panel (expanded, data loading) | Three `Skeleton h-4 w-full` lines inside the `bg-muted/50` panel |

**Phase 8 model outputs are fetched separately from Phase 7 rookie board data:**

- Phase 7 board data: `GET /rookie-board/{league_id}` — tiers, archetype, risk band, slot availability. `staleTime` 15 min.
- Phase 8 model data: `GET /prospects/model-outputs/{league_id}` — comps, hit-rate bucket, over/undervalue flag. `staleTime` 30 min (model outputs change less frequently than board rankings).

The two queries are joined client-side by `player_id`. If Phase 8 model data is still loading after Phase 7 board data resolves, the existing Phase 7 card renders fully — only the Phase 8 regions show skeleton states. The card does not hold its full render waiting for model data.

**Over/undervalue expand/collapse state:** Per-card local React state. Opening one card's sub-flags panel does not affect any other card. No global expand-all affordance in Phase 8.

## Implementation Notes for Executor

1. **Card extension, not card replacement:** Phase 8 adds regions below the existing Phase 7 `RookiePlayerCard` content. The existing name row, archetype row, risk row, and slot availability note are unchanged. Add a `shadcn Separator` with `my-2` (8px / `sm` token) below the existing content to visually separate Phase 7 and Phase 8 data regions.

2. **Two separate API queries, joined by player_id:** Phase 7 data and Phase 8 model outputs are fetched independently. `GET /rookie-board/{league_id}` returns Phase 7 data; `GET /prospects/model-outputs/{league_id}` returns Phase 8 model outputs. Client-side join via `player_id`. If Phase 8 data is still loading, render Phase 7 card in full with skeletons for the three new Phase 8 regions only — do not block the Phase 7 render.

3. **Outcome bucket color families match risk band families:** Hit → green (same as Low Risk); Mediocre → amber (same as Moderate Risk); Bust → red (same as High Risk). This is intentional. The user learns one color vocabulary from Phase 7 and the same families reinforce in Phase 8.

4. **Over/undervalue flag: expand toggle is a `<button>`, not a `<div>`:** The toggle must be a semantic button element with `aria-expanded` and `aria-controls`. The ChevronDown/Up icon is decorative — wrap it in a `<button>` with `aria-label="Show signal breakdown"` / `aria-label="Hide signal breakdown"`. Minimum touch target: `p-2` padding around the icon.

5. **Sub-flag strings are verbatim from backend:** The over/undervalue sub-flag direction + magnitude strings (e.g. "0.5 years older — slight negative") are returned by the API and rendered without client-side transformation. Frontend assigns color based on a `direction` enum field in the API response (positive / negative / neutral) — do not parse the string itself for color assignment.

6. **Comp role badges use outline variant with color override:** The ceiling/median/floor role badges use `Badge variant="outline"` with custom border and text color classes. This distinguishes comp role from outcome bucket — comp role uses outline, outcome bucket uses filled background. Both appear in the same comp row without visual collision.

7. **Sort by ADP Divergence hides tier dividers:** When the sort select is set to "ADP Divergence" or "Hit Rate", the board renders as a flat sorted list. `TierDivider` components are conditionally rendered only when sort is "Tier (default)". Pass a `showTierDividers: boolean` prop down from the board page to `TierGroup` components.

8. **Sort state is React state, not URL params:** The sort selection is ephemeral per session. Do not add it to the URL. Navigating away and back resets to "Tier (default)". This keeps the URL clean and avoids stale-sort state bookmarks.

9. **staleTime on model outputs query is 30 minutes:** Prospect model outputs are computationally expensive and change only when the model is re-run. Use `staleTime: 30 * 60 * 1000` on the TanStack Query for `GET /prospects/model-outputs/{league_id}`. Phase 7 board data retains its 15-minute `staleTime`.

10. **No new Lucide icons beyond ChevronDown/ChevronUp:** Phase 8 uses only the expand/collapse icons for the sub-flags panel. All other Phase 8 elements use text labels, not icons. ChevronDown and ChevronUp are already bundled with shadcn/ui — no new icon import required.

11. **Comp section ADP tier context is static text:** The "at this draft capital tier" string is a static label rendered next to the "Historical Comps" section header. It is not dynamic per prospect. The backend context is encoded in the comp objects themselves (comp outcomes are already tier-relative per D-05).

12. **Low confidence treatment is a Badge variant swap, not a color:** When hit-rate bucket is below minimum comp count, the hit-rate badge renders as `Badge variant="outline"` with `text-muted-foreground` — not a green/amber/red badge. This signals "no bucket assigned" rather than "low bucket." The over/undervalue flag renders as the muted string "Insufficient comps — low confidence" rather than a colored verdict.
