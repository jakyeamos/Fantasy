## Spacing Scale

Declared values (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline chip padding |
| sm | 8px | Compact row spacing, badge-to-text gaps |
| md | 16px | Default card padding, element spacing |
| lg | 24px | Section padding, card header padding |
| xl | 32px | Layout column gaps |
| 2xl | 48px | Major section breaks (e.g. above/below GM memo block) |
| 3xl | 64px | Page-level vertical breathing room |

Exceptions:
- Touch targets for tap-to-expand controls: minimum 44px height (matches existing `body::before` grid at 44px)
- Recommendation card summary row (`RecommendationCard`): 12px internal vertical padding (between xs and sm) for dense memo feel

**Source:** Inherited from existing codebase conventions. Default 8-point scale confirmed in `index.css` grid overlay (`background-size: 44px 44px`).

## Typography

| Role | Size | Weight | Line Height | Font Family | Usage |
|------|------|--------|-------------|-------------|-------|
| Body | 14px | 400 | 1.6 | Inter (`--font-body`) | Supporting metrics, secondary copy, explanation text |
| Label | 12px | 700 | 1.0 | Space Grotesk (`--font-label`) via `.terminal-label` class | Section eyebrows, confidence tier label, "WHY NOW" tag, all-caps metadata |
| Heading | 20px | 600 | 1.2 | Manrope (`--font-headline`) | Recommendation headline, card section title, GM memo primary action line |
| Display | 28px | 700 | 1.1 | Manrope (`--font-headline`) | GM memo opening state line ("Fragile Contender — act this week"), top-of-screen orientation label |

**Weights used:** 400 (regular) and 600/700 (semibold/bold) only. No other weights.

**Memo-specific:** Recommendation headline uses Manrope 20px/600, not Inter, to distinguish it from metric/body copy. This is the only place headline font appears at body scale — it signals "this is the call, not data."

**Source:** Font families confirmed from `index.css`. Sizes and weights derived from existing component patterns (`CardTitle` ~ 20px semibold, `.terminal-label` ~ 10px/700/uppercase). Display size is new for Phase 20 GM memo block.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `hsl(var(--background))` — dark: `221 69% 8%` | Page background, screen surface |
| Secondary (30%) | `hsl(var(--card))` — dark: `216 85% 10%` | All card surfaces including `RecommendationCard`, GM memo block, lineup summary tiles, dossier exploit section |
| Accent (10%) | `hsl(var(--primary))` — dark: `199 100% 74%` (sky blue) | Reserved for: (1) primary recommendation headline text, (2) `RecommendationCard` left border accent stripe, (3) "Full analysis" / CTA link text, (4) active confidence badge fill, (5) "What changes this call" toggle icon |
| Semantic — warning | `hsl(var(--accent))` — `156 100% 81%` (mint green) | Reserved for: "Downside of inaction" inline warning label only. Reuses existing `--accent` token. Do not use for any other purpose in Phase 20. |
| Destructive | `hsl(var(--destructive))` — dark: `4 77% 70%` | Low-confidence dossier banner (already established), no new destructive actions in Phase 20 |
| Muted | `hsl(var(--muted-foreground))` | Supporting metric values, secondary explanation text, "what changes this call" body |

Accent reserved for: recommendation headline text, left accent stripe on `RecommendationCard`, CTA link labels, active confidence badge, "what changes this call" toggle icon. Never use accent on metric rows, slot scores, or trade dimension scores.

**Source:** All token values read from `frontend/src/index.css`. Semantic-warning reuse of `--accent` mint green is deliberate — it reads "positive but cautionary" in this dark scheme and is already in the token system.

## Component Inventory

This section is specific to Phase 20 because the phase introduces one new shared component and four screen-level section restructures.

### New: `RecommendationCard`

The reusable unit used on every screen. Renders recommendation-first hierarchy.

**Structure (top to bottom):**
1. **Eyebrow label** — `.terminal-label` text, muted-foreground, uppercase. E.g. "PRIMARY RECOMMENDATION" / "BEST TRADE NOW"
2. **Headline** — Manrope 20px/600, `text-foreground`. The call. One sentence max. E.g. "Send Kelce + 2026 1st to Williams for Chase + 2025 2nd."
3. **Confidence badge** — inline Badge using `variant="default"` (accent fill) for High, `variant="secondary"` for Medium, `variant="outline"` for Low. Shows tier label only (e.g. "High confidence").
4. **Supporting factors** — 2–3 `text-sm text-muted-foreground` lines inside a `rounded-lg border border-border/50 bg-card/40 p-3` container. Each factor is one line. No sub-headers.
5. **Confidence reason** — single `text-xs text-muted-foreground` line. E.g. "Based on 14 trades — behavioral pattern is strong."
6. **Downside of inaction** — single line, prefixed with amber/mint warning dot (`bg-accent` 6px circle), `text-xs` in `text-accent-foreground`. E.g. "Waiting past the bye week drops acceptance probability by ~40%."
7. **What changes this call** — collapsible. Collapsed by default. Trigger is a chevron icon (`ChevronDown` from lucide-react) in `text-primary` next to `.terminal-label` text "WHAT WOULD CHANGE THIS". Expanded body is `text-sm text-muted-foreground` inside the same bordered container.

**Card chrome:** `border border-border/50 bg-card/75 rounded-xl`. Left edge: `4px solid hsl(var(--primary))` border on the left side only (use `border-l-4 border-l-primary`). This distinguishes `RecommendationCard` from metric cards (`Card` component) at a glance.

**Width:** Full-width within its column. Never placed in a grid at this phase — always stacked vertically.

### Existing: `Card` (src/components/ui/card.tsx)

Unchanged. Used for all supporting metric sections below the recommendation block. Distinguishable from `RecommendationCard` by absence of left accent stripe and primary border color.

### Existing: `Badge` (src/components/ui/badge.tsx)

Unchanged. Used for confidence tier and positional labels.

## Screen Contracts

### Screen 1: League Homepage (UX-02)

**Route:** `/` (index.tsx) — `LeagueCard` grid

**Current state:** Grid of `LeagueCard` components showing direction label, confidence, and top exploit window signal.

**Phase 20 change:** Replace the `LeagueCard` content with a GM memo block. The card chrome (Link wrapper, hover lift, `border-border/50 bg-card/75`) stays identical — only the interior changes.

**GM Memo Block layout (inside existing `LeagueCard` card chrome):**

Row 1 — Eyebrow + League name (unchanged):
- `.terminal-label` "WEEKLY BRIEF" in `text-muted-foreground`
- `CardTitle` league name at 20px
- Confidence `Badge` (top-right, unchanged)

Row 2 — Team state line (new):
- Display-scale copy (Manrope 28px/700) showing competitive state. E.g. "Fragile Contender"
- Sub-line: direction label in `text-sm text-muted-foreground`. E.g. "Title window is open — depth is the risk."

Row 3 — Top 3 next actions (new):
- `.terminal-label` "TOP 3 MOVES"
- Ordered list `<ol>` of 3 items, `text-sm text-foreground`, each prefixed with a `text-primary font-mono` rank number (1., 2., 3.)
- No bullets, no icons. Pure memo text.

Row 4 — Risk + Partner + Leverage (new, 3-column grid at `md:grid-cols-3`):
- "BIGGEST RISK" / "BEST TRADE PARTNER" / "BEST LEVERAGE" — each in a `rounded-lg border border-border/35 bg-card/45 p-3` tile
- `.terminal-label` eyebrow + `text-sm text-foreground` value below
- Trade partner tile links to `/league/$leagueId/managers/$managerId` on tap (navigable)

Row 5 — Footer (unchanged):
- Snapshot timestamp in `font-mono text-[11px] uppercase tracking-[0.16em] text-muted-foreground`
- "Full analysis" link label in `text-primary/75`

**Interaction:** The trade partner tile in Row 4 is a `<Link>` to the manager dossier. All other rows are display-only. The card itself remains a full-card link to the league drill-in.

**Data dependency:** `DashboardLeagueSummary` type will need `top_3_actions: string[]`, `biggest_risk: string`, `best_trade_partner: { manager_id: string; name: string }`, `best_leverage_point: string` fields added by Phase 17/18/19 engines. If fields are absent (null), Row 3 degrades to a single action line, Row 4 tiles show "Awaiting data" in `text-muted-foreground`.

### Screen 2: Lineup Screen (UX-03)

**Route:** `/league/$leagueId` (league.$leagueId.tsx) — the league overview panel

**Current state:** `LineupStrengthCard` (slot-by-slot score grid) followed by `RosterHygienePanel`, `TitleWindowPanel`, `TaxiIRSlotSummary`, etc.

**Phase 20 change:** Insert a 4-tile summary bar ABOVE `LineupStrengthCard`. The slot grid is not removed — it becomes the "detail" below the summary.

**4-tile Lineup Summary Bar layout:**

Container: `grid grid-cols-2 gap-4 md:grid-cols-4` placed directly above `LineupStrengthCard`.

Each tile: `rounded-xl border border-border/50 bg-card/75 p-4` with:
- `.terminal-label` eyebrow (`text-muted-foreground`)
- `text-base font-semibold text-foreground` player name or unit label
- `text-xs text-muted-foreground` one-line context (e.g. "2.4 pts above repl avg")

Tile 1 — "STRONGEST UNIT": position group with highest avg starter score above replacement. No navigation.

Tile 2 — "WEAKEST UNIT": position group with lowest avg. `.terminal-label` eyebrow in `text-destructive/80` instead of `text-muted-foreground` to flag it.

Tile 3 — "TITLE BLOCKER": single player or slot identified as the primary ceiling constraint. No navigation.

Tile 4 — "BEST UPGRADE": player name + trade target archetype. Tile is tappable: clicking routes to the trade screen (`/league/$leagueId` trades tab or `/trades`) pre-filtered to show upgrade options for that position. Tile uses `cursor-pointer group-hover:border-primary/30` hover state consistent with `LeagueCard`.

**Data dependency:** Derived from existing `lineup_score` endpoint data. If `data.slot_scores` is empty, all 4 tiles show Skeleton. If lineup data is loaded but summary fields are absent, tiles show "No data" in `text-muted-foreground`.

### Screen 3: Trade Screen (UX-04)

**Route:** `/trades` (trades.tsx)

**Current state:** `TradeInputPanel` (asset selector) + `EvaluationOutputPanel` (7-dimension score grid) side by side.

**Phase 20 change:** Insert a `RecommendationCard` block ABOVE the input/output panel pair. The existing panels are not removed.

**Trade Recommendation Header layout:**

Section label: `.terminal-label` "YOUR BEST MOVE RIGHT NOW" in `text-muted-foreground`, 16px top margin from page header.

Four `RecommendationCard` instances stacked vertically with `gap-4`:

Card 1 — "BEST TRADE TO SEND NOW": headline names the specific deal. CTA: "Evaluate This Package" button (`Button` default variant) that pre-populates `TradeInputPanel` with the recommended assets. Button appears inside the card below the supporting factors.

Card 2 — "BEST MANAGER TO APPROACH": headline names the manager. CTA: "View Dossier" link-button (`Button variant="outline"`) routing to `/league/$leagueId/managers/$managerId`.

Card 3 — "BEST PLAYER ARCHETYPE TO TARGET": headline describes the archetype (e.g. "Elite WR1 in year 2–4 of deal"). No CTA — display only.

Card 4 — "REROUTE IF TARGET UNAVAILABLE": headline describes fallback path. No CTA — display only.

**Collapsed state:** Cards 3 and 4 are collapsed by default — only eyebrow + headline visible, no supporting factors shown. Expand via chevron toggle. Cards 1 and 2 are expanded by default.

**Interaction:** "Evaluate This Package" pre-populates the `TradeInputPanel` below. This requires the trade screen to accept URL params or internal state for pre-population. The `RecommendationCard` passes assets via a callback prop or URL query string — executor decides implementation, but the interaction contract is: one tap from the recommendation → assets appear in the input panel.

**Data dependency:** Requires Phase 19 `TRADE2-04` outputs. If trade recommendations are absent (null or empty array), show a single `RecommendationCard` skeleton with `.terminal-label` "NO ACTIVE RECOMMENDATIONS" and body text "Run an ingest to surface trade opportunities."

**Route:** `/league/$leagueId/managers/$managerId` (league.$leagueId.managers.$managerId.tsx)

**Current state:** Tabbed `DossierPage` — Overview tab shows `DossierOverviewTab` (exploitation type, roster summary, trade stats).

Header row: `.terminal-label` "HOW TO TRADE WITH THIS MANAGER" in `text-primary`

Four `RecommendationCard` instances inside the container (borderless variant — omit card chrome, just stack content blocks with `border-b border-border/40` separators):

## Confidence Display Contract

The confidence block appears inside every `RecommendationCard`. Rules:

1. Never suppress a Medium-confidence recommendation. Show it with `Badge variant="secondary"` and the uncertainty reason line.
2. Never show a Low-confidence recommendation in the primary slot. Demote it to an "Alternative" sub-section or omit.
3. Confidence reason line (`text-xs text-muted-foreground`) must always state the evidence basis concisely. E.g. "Based on 14 trades — strong behavioral pattern" or "Based on 3 trades — treat as directional only."
4. "What changes this call" is always present and always collapsible. Never inline it at full length in the default view.
