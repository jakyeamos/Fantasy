# Phase 10 — UI Design Contract

> Visual and interaction contract for the Pick Accuracy & Draft Order phase. Generated by gsd-ui-researcher. Extends Phases 3–7 design contracts — all prior tokens and patterns are inherited unless explicitly overridden here.
>
> **Phase 10 is a targeted extension.** No new routes or pages are introduced. All UI changes are:
> 1. A `DraftOrderRuleForm` section added to the existing league settings area (`league.$leagueId.tsx`)
> 2. A `RuleCitation` inline text element appended to every pick value display surface (AssetChip, LeaguePickList row, EvaluationOutputPanel pick row, draft room pick displays)
> 3. A "Rule not configured" clickable placeholder that replaces pick values when the rule is absent
>
> **Note on `shadcn_new_init_required: false`:** shadcn/ui was initialized in Phase 3. Phase 10 does not require a new init — it inherits the existing installation. One new shadcn component (`radio-group`) is installed; all others are already present.

## Color

Inherited from Phase 3 shadcn CSS variable tokens. No new token roles added.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `hsl(var(--background))` — shadcn default near-white/near-black | Page background |
| Secondary (30%) | `hsl(var(--card))` — shadcn card surface | League settings card, form section background |
| Accent (10%) | `hsl(var(--primary))` — shadcn default blue | "Rule not configured" clickable text; "Save Rule" button (primary variant); active RadioGroup selection indicator |
| Destructive | `hsl(var(--destructive))` — shadcn default red | Not used in Phase 10 — no destructive actions |

**Phase 10 color specifics:**

- **Rule citation text (configured state):** `text-muted-foreground text-xs` — same treatment as Phase 6 timing reasoning strings; subdued, not competing with the pick value itself
- **"Rule not configured" placeholder (unconfigured state):** `text-primary text-xs underline cursor-pointer` — accent color signals an actionable link, not a passive error message; no red/destructive treatment because this is an onboarding gap, not a failure
- **Save button success flash:** After successful save, the "Save Rule" button briefly shows "Saved" with `text-green-600` for 1.5s, then reverts to default label. No toast or alert — the inline mutation works within the form card.
- **Blocked pick values (unconfigured rule):** The pick value number is replaced by the "Rule not configured" placeholder string — no red background, no error badge. Same visual weight as an empty-state string.

**Dark mode:** OS-default via `prefers-color-scheme` — same as Phases 3–7. No mode toggle in Phase 10.

## Component Inventory

Phase 10 introduces no new routes. The following describes in-place additions to existing components and one new form section.

### DraftOrderRuleForm (new section within `league.$leagueId.tsx`)

**Placement:** Added as a new `<Card>` section below the existing `LeaguePickList` in the league drill-in page (`league.$leagueId.tsx`). Not a separate page or tab — a single-page form per D-09 and D-10.

**Layout (top to bottom within the card):**

```
[Card Header]  "Draft Order Rule"   [Section heading, 18px/600]
[Card Content]
  [Description]  "Configure how this league's draft order is determined."  [Body, 14px/400, text-muted-foreground]

  [Field 1] Non-playoff order basis
    Label: "Non-playoff ordering"  [Body, 14px/400]
    RadioGroup (vertical, 2 options):
      ○  Inverse standings
      ○  Max points for
    Description: "How are non-playoff teams ordered at draft time?"  [Label, 12px/400, text-muted-foreground]

  [Field 2] Playoff-team ordering
    Label: "Playoff team ordering"  [Body, 14px/400]
    Select (shadcn Select component):
      Options: "By playoff finish" / "By regular season record" / "By regular season points for"
    Description: "How are teams that made the playoffs slotted at the end of the draft order?"  [Label, 12px/400, text-muted-foreground]

  [Field 3] Tiebreaker
    Label: "Tiebreaker"  [Body, 14px/400]
    Select (shadcn Select component):
      Options: "Points against (higher = worse draft slot)" / "Points for (lower = better draft slot)" / "Coin flip / commissioner discretion"
    Description: "How are tied teams in the non-playoff ordering separated?"  [Label, 12px/400, text-muted-foreground]

  [Save Row]
    [Save Rule]  Button, variant="default", size="sm"
    [Mutation state]  see Interaction States below
```

**Fully configured state:** All three fields have a saved value. The card shows the form in a "confirmed" layout: field values are displayed as read-only text with a small "Edit" link (Body, 14px/400, `text-primary underline cursor-pointer`) beside the "Draft Order Rule" heading. The form fields collapse to display-only until Edit is clicked. This prevents accidental re-saves after configuration is complete.

**Partially configured state (any field missing):** All three fields remain visible and editable. The "Save Rule" button is disabled until all three fields have a non-null value. Below the button, show the text "All three fields are required before pick projections unlock." (Label, 12px/400, `text-muted-foreground`).

**Component structure:**
- Outer wrapper: `<Card>` with `CardHeader` (`CardTitle` "Draft Order Rule") and `CardContent`
- Form: standard `<form>` with `onSubmit` handler; no React Hook Form required (3 controlled selects + 1 radio group)
- RadioGroup: shadcn `RadioGroup` with `RadioGroupItem` + `Label` for each option
- Selects: shadcn `Select` with `SelectTrigger`, `SelectContent`, `SelectItem`
- Save button: shadcn `Button variant="default" size="sm"` with mutation loading state

### RuleCitation (new element added to all pick value surfaces)

**What it is:** A single line of 12px `text-muted-foreground` text (or a 12px `text-primary underline cursor-pointer` text in the unconfigured state) appended below any displayed pick value.

**Configured state text:** `"Using: {order_basis_label} · {playoff_ordering_label}"` where:
- `inverse_standings` renders as `"Inverse standings"`
- `max_points_for` renders as `"Max points for"`
- `{playoff_ordering_label}` is the human-readable string for the playoff ordering (e.g. `"Playoff teams by finish"`, `"Playoff teams by record"`, `"Playoff teams by points for"`)

Example: `"Using: Max points for · Playoff teams by finish"`

**Unconfigured state text:** `"Rule not configured — tap to set up"`

**Clickability:** Both states navigate to the league settings rule editor (the `DraftOrderRuleForm` section on `league.$leagueId.tsx`). Use TanStack Router `<Link>` with appropriate `to` and `params` values. The entire text is the link target — no separate chevron or arrow icon.

**Layout:** Renders as a new last row in the pick display, below any existing timing reasoning string (Phase 6). Uses `mt-1` top margin to keep consistent spacing with Phase 6 reasoning strings.

**Affected surfaces (all must render `RuleCitation`):**

| Surface | Component | Placement |
|---------|-----------|-----------|
| League pick list | `LeaguePickList` — per-pick row | Below timing reasoning string (second line of row second block) |
| Trade evaluator pick chip | `AssetChip` pick variant | Below timing reasoning string (third line of chip) |
| Trade evaluator pick detail | `PickValueSummaryRow` (`EvaluationOutputPanel`) | Below timing reasoning string (fourth line) |
| Draft room pick context | Any pick display component in draft room route | Below timing reasoning string |

**Blocked pick value (unconfigured rule, any surface):** The pick numeric value is not displayed. Replace the value with the "Rule not configured — tap to set up" citation text only. Do not show a placeholder value (e.g. `0` or `—`). Do not show the timing badge. The slot projection badge is also hidden. Only the pick identity text (year + round) and the clickable unconfigured citation are shown.

## Interaction States

Every data region that fetches from the API must implement all four states (inherited from Phase 3):

| State | Behavior |
|-------|----------|
| Loading | Replace content with matching-height `Skeleton` components; no spinner |
| Success | Render data |
| Empty / Unconfigured | Render "Rule not configured — tap to set up" clickable citation text; no pick value displayed |
| Error | Render error state copy inline; TanStack Query retry handles refetch |

**DraftOrderRuleForm mutation states:**

| State | Button Label | Additional UI |
|-------|-------------|---------------|
| Idle (unsaved) | "Save Rule" | enabled when all 3 fields filled; disabled with `opacity-50` when any field is null |
| Saving (in-flight) | "Saving..." | button disabled, `opacity-50` |
| Success (1.5s flash) | "Saved" | button text `text-green-600`; reverts to "Save Rule" after 1.5s; form switches to confirmed/display mode |
| Error | "Save Rule" (reverts) | Inline error text below button: "Save failed. Try again." (Label, 12px/400, `text-destructive`) |

**RuleCitation link navigation:** Navigating from a citation (in trade evaluator or draft room) to the rule editor on `league.$leagueId.tsx` must preserve the existing scroll position contract. Use TanStack Router `<Link>` with `hash="draft-order-rule"` targeting the `DraftOrderRuleForm` card's `id="draft-order-rule"` attribute so the page scrolls to the form automatically.

**Pick value blocking (unconfigured rule):**
- `GET /picks/{league_id}` returns picks with `rule_citation: null` and no numeric value when the rule is not configured
- Frontend detects `rule_citation === null` and renders the blocked state (no value, no timing badge, only clickable citation text)
- This applies on all surfaces — do not special-case per surface; the `RuleCitation` component handles both states via a prop

## Implementation Notes for Executor

1. **No new routes — targeted form injection:** The entire frontend scope is: (a) add `DraftOrderRuleForm` card to `league.$leagueId.tsx`, (b) add `RuleCitation` component consumed by all pick display surfaces, (c) update `LeaguePickList`, `AssetChip` pick variant, `PickValueSummaryRow`, and any draft room pick displays to render `RuleCitation`. That is the full frontend scope.

2. **`RuleCitation` is a shared component:** Create `src/components/picks/RuleCitation.tsx`. It accepts `{ citation: string | null, leagueId: string }` and renders either the configured or unconfigured state. All affected surfaces import and use this single component — never inline the citation text directly in a surface component.

3. **Blocked state removes timing badge:** When `citation === null`, the `AssetChip` pick variant must not render the `TimingBadge` or timing reasoning string from Phase 6. The blocked chip shows only: pick identity text (year + round) + `RuleCitation` unconfigured state. This collapses the chip back to a near-Phase-5 layout.

4. **API endpoint for rule CRUD:** New endpoint `PUT /leagues/{league_id}/draft-order-rule` handles both create and update (upsert). The frontend form uses `useMutation` with `invalidateQueries(['picks', leagueId])` on success so all pick value surfaces automatically re-fetch with the newly configured rule.

5. **`rule_citation` is a backend-rendered string:** The backend renders the full citation string (e.g. `"Using: Max points for · Playoff teams by finish"`) on every `PickValue` response. The frontend does not assemble this string from raw rule fields — it receives the pre-rendered string in the `rule_citation` field of `PickValue`. When `rule_citation` is `null`, the unconfigured state is shown.

6. **Confirmed (read-only) form state:** After a successful save, the `DraftOrderRuleForm` switches from edit mode to a display-only view showing the three saved values as plain text, with an "Edit" link (`text-primary underline cursor-pointer`) next to the card title. Clicking "Edit" re-enables the form fields and shows the Save button. This prevents the form from looking perpetually editable after initial setup.

7. **`id="draft-order-rule"` on the form card:** The outer `<div>` or `<section>` wrapping the `DraftOrderRuleForm` card must have `id="draft-order-rule"` so that `<Link hash="draft-order-rule">` navigation from pick citation text scrolls to the correct position on the league detail page.

8. **Scroll behavior on citation navigation:** Use `behavior: 'smooth'` scroll in TanStack Router's `hashScrollIntoView` config or equivalent. The user is navigating from a trade/draft context into the league settings — smooth scroll gives orientation cues.

9. **RadioGroup vs. Select:** Field 1 (non-playoff order basis) uses `RadioGroup` — only 2 options, both should be visible without a dropdown. Fields 2 and 3 (playoff ordering and tiebreaker) use `Select` — 3 options each; a dropdown is appropriate and saves vertical space.

10. **TanStack Query key alignment:** Pick values must be cached under `['picks', leagueId]`. The `DraftOrderRuleForm` mutation calls `queryClient.invalidateQueries({ queryKey: ['picks', leagueId] })` on success. This ensures all pick surfaces across the app re-fetch with the updated rule — no manual cache busting required.
